# 자동 전략 탐색 범위 조사

조사일: 2026-10-29. 현행 코드·테스트와 소규모 합성 시나리오를 검토했다. 이 문서는 조사 결과이며 새 탐색 축이나 계산 계약을 확정하지 않는다.

## 결론

**지금은 자동 탐색 축을 추가할 근거가 충분하지 않다.** 목표 미충족과 적은 카드 수가 관찰됐지만, 기존 축 밖의 대안이 같은 목표·가정에서 더 나은 결과를 내는지 비교하지 않았다. 카드 수가 적다는 사실만으로 축이 부족하다고 판단하지 않는다. 우선 실패 유형과 후보 탈락 사유를 더 넓은 표본에서 측정하고, 실제 누락 후보를 확인한 뒤 해당 축만 대조 실험한다.

## 실제 호출 경로와 기존 범위

`AnalysisRuntime`은 기존 전략 파이프라인으로 계산한 `effective.params`를 `useStrategyOptimization`에 넘긴다. Worker는 이를 `LegacySimulationAdapter`로 변환하고 `StrategyOptimizer`를 Monte Carlo 설정과 함께 실행한다. 대시보드와 PDF는 이 최적화 결과를 소비한다. 기존 legacy 추천 경로는 별도 후보 생성기를 사용하므로 네 축의 결과와 혼동하지 않는다.

`StrategyGenerator`의 자동 후보 축은 은퇴 나이, 국민연금 개시 나이, 계좌 인출 정책, 소비 패턴이다. 현행 계획은 기준 후보로 보존한다. 은퇴 나이는 현재 나이와 계획 종료로 거른 58~65세 격자에 현재 계획 나이와 유효한 조기은퇴 목표 나이를 더한다. 국민연금은 유효한 60·65·70세 중 선택하며 해당 연금이 없거나 격자 전체가 계획 밖이면 기존 설정을 유지한다. 없는 계좌의 인출 정책은 확장하지 않는다.

순서는 후보 생성 → HARD 사전 제거 → 결정론 시뮬레이션·목표 평가 → HARD 사후 제거 → 결정론 순위·동일 결과 제거 → 후보 선별 → Monte Carlo 검증 → 페르소나 배정이다. 기본 선별 상한은 12개, 선별 시행은 200회이며 표시할 승자는 전체 시행으로 다시 검증한다. 페르소나 배정은 배타적이고 여유형은 소비 패턴 조건을 가지므로 카드가 3개 미만이어도 정상이다. 조기 국민연금도 비교 원장의 요건을 충족할 때만 추천 자격을 얻는다. 자세한 계약과 근거는 [후보 생성 축](wiki/concepts/후보%20생성%20축.md), [평가 파이프라인 순서](wiki/concepts/평가%20파이프라인%20순서.md), [추천 페르소나 배정](wiki/concepts/추천%20페르소나%20배정.md)을 따른다.

## 실측과 제한

2026-10-29 다음 명령을 실행했다.

```bash
SCENARIO_COUNT=12 HARNESS_OUT=/tmp/nextlife-axis-review npm run harness:mass
npx vitest run src/tests/core/strategy/StrategyGenerator.test.ts src/tests/core/strategy/StrategyOptimizer.test.ts src/tests/core/recommendation/RecommendationEngine.test.ts
```

고정 시드 `20260829`의 앞 12개 합성 시나리오를 하니스가 기존 엔진과 Monte Carlo 경로로 실행했다. 시나리오의 JSON 직렬화·목표 마이그레이션 왕복을 검사했지만 전체 UI 조작·암호화 저장·정규화·실제 브라우저 Worker까지 검증한 것은 아니다. 합성 표본은 사용자의 분포를 대표하지 않으며 축 추가 전후 비교도 아니다. 하니스 실행은 1개 테스트로 완료했고, 관련 단위 테스트는 74개 통과했다.

| 관찰 | 결과 | 해석 |
|---|---:|---|
| 실행 성공 / 실패 | 12 / 0 | 이 표본에서 실행 예외는 없었다. |
| 최종 결과 `ok` | 10건 | 그중 3건은 추천 후보 수가 3개 미만이다. 수가 적다는 것만으로 실패는 아니다. |
| 최종 추천의 목표 달성 확률이 모두 0% | 1건 | 7번은 후보 217개를 생성·결정론 통과했고 12개를 선별했으며, 확정된 추천 1개의 목표 달성 확률이 0%였다. 모든 가능한 전략이 불가능하다는 뜻은 아니다. |
| HARD 조건으로 생존 후보 없음 | 1건 | 12번은 후보 217개 모두 생활비 부족 HARD 사후 판정으로 탈락했다. 새 축이 이를 해결하는지는 확인하지 않았다. |
| 일부 후보 HARD 탈락 | 2건 | 3번은 조기은퇴 나이 사전 탈락 18건, 6번은 자산 고갈 방지 사후 탈락 153건이 있었지만 각각 추천이 나왔다. |

1번과 5번은 `ok`이면서 추천 후보가 각각 하나였다. 수집된 요약에는 각 후보가 페르소나 자격·중복 제거·선별 중 어느 단계에서 빠졌는지 충분한 정보가 없어 원인을 특정하지 않는다. 표본은 12건뿐이므로 이 빈도를 사용자 비율이나 성능 평가로 일반화하지 않는다.

## 축별 검토

| 후보 | 예상 효용 | 현행 지원 및 비용·호환성 | 판단 |
|---|---|---|---|
| 기존 은퇴·국민연금 나이 격자의 촘촘함 또는 범위 | 격자 사이의 실행 가능한 시점을 놓친 경우 개선 가능 | 기존 엔진 경로는 있으나 현재는 나이를 제한해 생성한다. 축별 값 수가 늘면 결정론 후보 수는 다른 축과 곱해진다. 후보 상한 도달 시 순회 순서로 잘리며, shortlist 12개는 자동 확장되지 않는다. | **우선 조사 후보.** 실제 격자 밖 대안을 같은 조건에서 비교해야 한다. |
| 사적연금 독립 개시 나이 | 퇴직 전후 현금흐름 선택지가 생길 가능성 | 현행 자동 생성은 은퇴 나이와 연결한다. 독립 탐색에는 엔진·저장·적용 경로와 법정 연령의 일관성 확인이 필요하다. | 근거 부족. 입력·적용 가능성과 사용자 효용을 먼저 확인한다. |
| 현금 버퍼 | 하락기 인출 계획을 다르게 설계할 가능성 | 생성기는 인출 경로에 연결되지 않았다고 명시한다. 값만 격자에 넣으면 효과 없는 후보가 된다. 원장·인출 규칙과 기존 데이터 기본값 설계가 먼저다. | 축 추가 보류. |
| 동적 가드레일 | 시장 변동에 따른 소비 조정 전략을 비교할 가능성 | 현행 동적 소비 규칙이 없다. HARD 생활비, 목표 확률, 연도별 원장, Worker·PDF에 미치는 영향을 설계해야 한다. | 별도 기능 단계가 필요하다. |
| `max_sustainable` 소비 모드 | 목표액 대신 한계 소비액을 탐색하는 질문에 답할 가능성 | 현행 격자는 비교 기준을 맞추기 위해 `target`으로 고정한다. 내부 코드의 존재는 production 자동 탐색 지원을 뜻하지 않는다. 목표·확률 비교 기준과 저장 호환성을 다시 정의해야 한다. | 현 단계에서 축으로 추가하지 않는다. |

현재 최대 이론 격자는 은퇴 나이 최대 10 × 국민연금 3 × 인출 정책 4 × 소비 패턴 3 = 360개이며 기준 후보를 더해 최대 361개다. 기본 생성 상한 1,000보다 작다. 축 크기를 배로 늘리면 결정론 시뮬레이션 수가 최대 배가 될 수 있지만, 중복 제거·HARD 탈락과 12개 shortlist 때문에 Monte Carlo 비용이 같은 비율로 늘어난다고 단정할 수 없다. 기기별 경과 시간과 메모리는 이번에 측정하지 않았다.

## 다음 검증 조건

1. 더 넓은 고정 시드 표본에서 생성·HARD 탈락 코드·중복 제거·선별·페르소나 자격·검증 오류를 별도로 집계한다. 계산 실패를 목표 미충족과 합치지 않는다.
2. 실제 누락 사례를 선정해 **기존 격자와 확장 후보를 동일 입력, 목표, 평가 순서, 난수 시드 및 시행 수로 비교**한다. 개선 여부뿐 아니라 HARD 충족, 현상 유지 기준, 적용 후 재현성 및 기존 사용자 데이터 결과를 확인한다.
3. 사용자 UI 생성 → 저장·정규화·마이그레이션 → 추천 후보 → Worker → 적용과 재분석의 도달 가능성을 확인한다. 엔진에 타입이나 코드가 있다는 것만으로 production 기능이라고 표시하지 않는다.
4. 후보 수·중복 수·선별 상한과 저사양 기기의 실행 시간·메모리를 측정한다. 상한으로 잘리는 경우 생성 순서 편향을 검토한다.
5. 결과가 축 추가를 정당화하면 별도 범위를 정하고 관련 위키·ADR, 단위·회귀 테스트와 대시보드·PDF 일관성을 함께 갱신한다.
