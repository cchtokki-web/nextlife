# 사적연금 채널링

## 결정

Lifetime Utility Score 전환 프로젝트의 네 번째 개선 전략(Phase 4)으로, 사적연금을 55세부터
조기 수령해 ISA에 재투자하고 신규 사적연금 계좌를 은퇴 전까지 유지하는 전략을
`RecommendationEngine`이 자동으로 탐색·추천하도록 한다. 사용자가 켜고 끄는 입력 폼은 만들지
않는다 — Phase 3(배당 재투자 최적화)와 동일하게 AI 추천 전용 축이다.

- **개시 나이와 은퇴 나이의 분리**: 사적연금 수령을 `retirementAge`와 무관하게 만 55세부터
  시작할 수 있게 하되(재직 중 수령 포함), 이는 사용자가 임의로 지정하는 범용 옵션이 아니라
  이 전략이 켜졌을 때만 적용되는 전용 "브릿지 구간" 개념이다.
- **브릿지 구간(55세 ≤ currentAge < retirementAge, `!isRetired`)의 월 인출액**은
  `min(계좌 잔액, privatePensionLimit ÷ 12)`다. 여러 계좌가 있으면 기존 은퇴 후 로직과
  동일한 "합산 후 순차 소진" 방식으로 한도를 계좌 간에 공유한다. 세후 순액은 생활비 재원이
  아니라 기존 ISA 계좌(첫 번째 것)의 `currentValue`에 추가 납입처럼 더한다 — 재직 중이라
  생활비는 이미 근로소득(이 시뮬레이터가 모델링하지 않는 영역)으로 충당된다고 가정한다.
  세금은 기존 `getPrivatePensionIncomeTaxRate(currentAge)`를 그대로 적용한다.
  `retirementAge` 도달 이후에는 이 전략의 영향이 사라지고 기존 은퇴 후 인출 로직이 그대로
  적용된다.
- **다중 계좌는 하나의 통합 on/off 전략으로 취급한다.** Phase 3처럼 계좌별 2^N 조합 탐색은
  하지 않는다 — 켜지면 보유한 모든 사적연금 계좌가 함께 전환되고, 신규 계좌 1개가 함께
  추가된다.
- **신규 사적연금 계좌**는 정확히 1개, 월 75만원(연 900만원 세액공제 한도) 고정 납입이다.
  수익률·투자종류·통화는 사용자의 기존 사적연금 계좌(배열의 첫 번째)를 그대로 복사한다.
  이 계좌는 브릿지 조기 인출 대상에서 제외한다.
- **전제 조건**: 사적연금 ≥ 1개, ISA ≥ 1개, `retirementAge > 55`. 하나라도 불충족이면
  후보 자체를 생성하지 않는다(no-op, 추가 시뮬레이션 없음).
- **평가는 Phase 1~3 최종 결과 대비 단일 재시뮬레이션(최대 1회)이다.** 자산별 독립 평가는
  하지 않는다. Utility가 개선되면 채택(`true`), 아니면 `false`가 아니라 `null`로
  "권장 없음"을 표현한다 — Phase 3와 같은 패턴이다.

## 배경

"Lifetime Utility Score 전환 프로젝트"는 Phase 1(6→5차원 그리드), Phase 2(생활비 배수),
Phase 3(배당 재투자 최적화, `develop` 병합 완료)까지 마쳤다. 이번 작업은 사용자가 제시한
전략 — 개인연금을 55세에 개시해 ISA에 재투자하고, 신규 개인연금을 만들어 퇴직 전까지
납입하는 것(절세 및 상속 대상이 없을 때 생활비 극대화가 목적) — 을 네 번째 전략으로 얹는다.

사전 조사가 이미 필요한 인프라 대부분이 있음을 확인했다.

- `privatePensionStartAge` 필드는 `7dbc016`("사적연금 수령 개시 나이 설정 기능 제거")에서
  의도적으로 제거되어, 현재 사적연금 수령 개시 나이는 항상 `retirementAge`(최소 55세로
  하한)로 고정돼 있다. 은퇴 전 사적연금 인출 경로는 `7dbc016` 이전에도 존재한 적이
  없다 — 그 커밋이 막은 것이 아니라 애초에 지원된 적이 없다.
- 은퇴 전 모든 계좌의 `monthlyContribution`은 이미 적용되고 은퇴 시작과 함께 일괄
  중단되므로, "은퇴 나이까지 새 연금 계좌에 납입"은 신규 로직 없이 신규 계좌를 후보 params에
  추가하는 것만으로 성립한다.
- `TaxSettings.privatePensionLimit`(연 1,500만원)과 그 한도까지만 인출하는 기존 캡 로직은
  브릿지 구간 인출액 산정에 그대로 재사용할 수 있다.
- `getPrivatePensionIncomeTaxRate(age)`는 은퇴 여부와 무관하게 나이 구간별로 세율을
  정하므로, 55세부터 조기 인출해도 세율 계산 로직을 바꿀 필요가 없다.
- 상속 목표 0 처리(`computeBequestAdequacyRaw`)와 생활비 배수 탐색
  (`generateSpendingAdjustmentCandidates`)이 이미 있어, "상속 대상 없을 시 최대 생활비"는
  이 작업이 확보하는 절세분을 자동으로 생활비 증액에 연결해 줄 기존 인프라가 담당한다.

## 기각한 대안과 범위 제외

기각한 대안(검토 후 다른 안을 선택):

- **`privatePensionStartAge` 필드를 그대로 되살리는 것.** 사용자가 임의로 지정하는 범용
  옵션 재도입 대신, 이 전략이 켜졌을 때만 적용되는 전용 "브릿지 구간" 개념으로 구현한다 —
  `7dbc016`의 단순화 결정을 되돌리지 않는다.
- **계좌별 독립 on/off 조합 탐색(Phase 3처럼 N개 계좌 개별 평가).** 대신 하나의 통합
  전략으로 근사한다 — 추가 시뮬레이션 비용을 최대 1회로 묶기 위해서다.
- **사용자가 선택하는 별도의 "대안 전략" UI.** Phase 3와 동일하게 개선되면
  `recommendedResult`에 자동 병합한다.

범위 제외(이번 스펙이 다루지 않음):

- 사용자가 브릿지 채널링을 수동으로 켜고 끄는 입력 폼 UI — AI 추천 전용이다.
- 신규 연금 계좌의 세액공제 한도 초과분 처리, 여러 신규 계좌 추가 — 신규 계좌는 정확히
  1개, 월 75만원 고정이다.
- "상속 대상 없을 시 최대 생활비" 자체를 위한 신규 유틸리티/탐색 로직 — 기존
  `targetBequest=0` 처리와 생활비 배수 탐색이 이미 담당한다.
- 화면/PDF에 이 전략을 별도로 강조하는 문구·아이콘 등 세부 UI.

## 호환성 처리

`StrategyRecommendation`에 `recommendedPrivatePensionChanneling: boolean | null` 필드를
추가한다 — 전제 조건 불충족이거나 개선이 없으면 `null`이다. `recommendedPlan`·
`recommendedAssetReinvestment`와 마찬가지로 독립된 세 번째 축으로 관리하며, 기존 축의 뜻을
바꾸지 않는다.

스펙(`[[2026-07-28-private-pension-channeling-design]]` 107행)은 `SimulationParams`의
내부용 플래그(예: `params.privatePensionBridgeChannelingEnabled?: boolean`)를 예시로
제안했지만, 구현은 다른 경로를 택했다. 브릿지 인출 분기는 계좌 단위 필드
`PrivatePension.earlyChannelingEnabled?: boolean`(`src/core/entities/types.ts` 89행)로만
켜진다 — params 전역이 아니라 사적연금 계좌마다 개별로 설정한다. `SimulationEngine.ts`의
브릿지 분기(`pension.earlyChannelingEnabled` 사용처, 1497행)가 실제 발동 조건의 source of
truth이고, `types.ts` 89행 주석도 그렇게 명시한다. 이 필드는 UI 입력 폼에 노출하지 않으며,
미지정 시 기존 `isRetired` 인출 블록과 결과는 그대로다 — 새 분기는
`!isRetired && currentAge >= 55` 조건에서만 동작하는 병렬 분기이고, 기존 은퇴 후 인출 코드
경로는 한 줄도 바뀌지 않는다.

전략이 채택되면 `itemizedContributions`와 `reasons`에 항목이 자동으로 추가되고
`recommendedResult`가 Phase 4까지 반영된 최종 결과로 갱신된다. Before/After 토글·PDF·AI
어드바이저 프롬프트는 이미 `recommendedResult`를 소비하므로 코드 변경 없이 새 추천을
반영한다 — 신규 UI 코드는 만들지 않는다.

검증은 전제 조건 3가지(사적연금 없음/ISA 없음/`retirementAge<=55`) 각각의 no-op, 한도 캡,
계좌 간 한도 공유, 기각 케이스를 단위 테스트로 고정하고, 브릿지 구간 인출액이 ISA
`currentValue`에 정확히 합산되는지·`retirementAge` 이후 기존 로직으로 정확히 복귀하는지를
`SimulationEngine` 테스트로 고정한다. 사적연금+ISA를 함께 가진 fixture가 있는 기존
`RecommendationEngine.test.ts`의 characterization 값은 이 결정으로 실제 바뀔 수 있어,
구현 단계에서 전체 테스트를 실행해 영향을 확인하고 실제 동작 변화라면 값을 갱신한다 —
Phase 3 때와 동일한 주의사항이다. 성능 예산은 Phase 4의 추가 비용(최대 1회 시뮬레이션)이
기존 예산 안에 드는지 별도 케이스로 확인한다.

## 영향받는 개념

[[사적연금 과세와 연말정산]] — 브릿지 구간 인출이 `getPrivatePensionIncomeTaxRate`와
`privatePensionLimit` 저율과세 한도를 은퇴 후가 아니라 55세부터 새로 적용하는 시점으로
넓힌다. 계산식 자체는 재사용이며 바뀌지 않는다.
