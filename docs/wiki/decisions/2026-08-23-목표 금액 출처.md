# 목표 금액 출처

## 결정

`RetirementGoal`에 목표 금액의 출처 표시를 **선택 필드**로 추가한다. 값이 없으면 미확정이다
— 필수 필드로 만들거나 기본값을 「확정」으로 두는 안은 기각했다. 그러면 표시가 없는 기존
저장 데이터가 전부 확정으로 승격되는데, 그것이 지시가 금지한 바로 그 일이기 때문이다.

- `toggleGoal`이 목표 선택 순간 깔아 주는 씨앗(`LIVING_EXPENSE_STABILITY`·
  `COMFORTABLE_SPENDING`은 계획의 `targetMonthlySpending`, `INHERITANCE`는
  `targetBequest ?? targetMonthlySpending * 24`)에는 출처 표시를 붙이지 않는다.
  `updateGoal`을 통해 사용자가 직접 입력한 값에만 붙인다.
- **미확정 `targetValue`는 shortfall 계산과 HARD/SOFT 판정에 참여하지 않는다.** 계획의
  다른 축(계획 자체의 목표 생활비 등)은 그대로 쓴다 — 없애는 것은 사용자가 말한 적 없는
  숫자를 근거로 실패를 선언하는 일뿐이다.
- **체감 커브는 확정된 목표금액이 있으면 그것을 기준으로 파생한다.** 없으면 종전대로
  계획의 값을 쓴다 — 확정되지 않은 씨앗을 기준으로 파생하지 않는다.
- **화면은 미확정 값이 아직 제안임을, 확정하려면 무엇을 해야 하는지를 밝힌다.** 미확정
  값이 판정에 참여하지 않는다는 것은 사용자가 「반드시 지키기」를 골라 두고도 그 금액이
  강제되지 않는다는 뜻이므로, 그 상태를 숨기면 이번 수정이 목표를 조용히 약화시킨다.
  문구는 구현 단계에서 정하되 제안값 자체는 지금 쓰는 것을 그대로 쓴다 — 새 숫자를 만들지
  않는다.

## 배경

승인 지시(`docs/known-issues.md` 2번, 2026-08-23)는 시스템이 깔아 준 seed를 사용자가
확정한 목표금액으로 취급하지 말고, 추천/초기값과 사용자 확정값을 의미적으로 분리하며,
사용자가 확인하지 않은 숫자가 shortfall이나 HARD/SOFT 실패를 영구적으로 발생시키지 않게
하라고 지시했다.

지시대로 먼저 조사한 결과는 **구별 불가**다. `RetirementGoal.targetValue`는 씨앗과 사용자
입력이 같은 자리에 같은 형태로 저장된다. `toggleGoal`이 목표를 고르는 순간 이미
`targetValue: defaultTarget(type)`을 써넣고, 사용자가 그 뒤에 고쳤는지는 아무데도 남지
않는다. 편집 경로(`updateGoal`)는 분리돼 있어 앞으로는 표시할 수 있지만, 이미 저장된 값의
출처는 복원할 방법이 없다.

## 기각한 대안과 범위 제외

기각한 대안(검토 후 다른 안을 선택):

- **출처 표시를 필수 필드로 만들거나 기본값을 「확정」으로 두는 것.** 기존 저장 데이터가
  전부 확정으로 승격되어 지시를 어기게 된다 — 기본값은 「미확정」이어야 한다.

범위 제외(이번 스펙이 다루지 않음):

- **새 금융 가정·숫자를 만드는 것.** 씨앗 규칙(`targetMonthlySpending`,
  `targetBequest ?? targetMonthlySpending * 24`)은 그대로다. 바뀌는 것은 그 값의
  「지위」뿐이다.
- **씨앗 자체를 없애는 것.** 빈 칸으로 두면 사용자가 매번 숫자를 지어내야 한다. 문제는
  씨앗의 존재가 아니라 그것이 확정으로 취급되는 것이다.

## 호환성 처리

기존 저장 시나리오는 마이그레이션하지 않는다. 출처 표시가 없는 기존 `targetValue`는 —
그것이 원래 씨앗이었든 사용자가 실제로 입력한 값이었든 구별할 수 없으므로 — 전부
미확정으로 취급한다. 그 결과 기존에 HARD로 저장된 목표라도 표시가 없으면 더 이상 그
금액으로 shortfall이나 HARD 미달을 강제하지 않는다.

이는 한쪽 방향으로만 완화된다: 이전에 씨앗값 때문에 잘못 강제되던 HARD 판정이 느슨해지는
쪽으로만 바뀌고, 사용자가 실제로 확정한 적 없는 숫자가 새로 강제되는 방향으로는 바뀌지
않는다. 다만 화면은 그렇게 미확정으로 강등된 HARD 목표가 「아직 제안」 상태임을 밝혀야
하므로, 사용자가 그 목표를 실제로 확정하려면 이제 `updateGoal`을 통해 직접 값을 입력해야
한다.
