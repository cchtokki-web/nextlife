# LLM Wiki 색인

작업 시작 전 여기서 관련 노트를 찾는다. 규칙은 [[스키마]], 사용법은 [[위키 사용법]].

노트는 사람이 쓰고 검수한 글이다. 무결성 테스트는 경로와 링크만 검사할 뿐 본문이 코드와
여전히 맞는지는 보지 않는다. 노트를 근거로 판단하기 전에 그 노트의 `## 근거`가 가리키는
코드를 직접 열어 본다.

## 개념

계산 계약과 도메인 규칙. 시점과 무관하게 현재 계약을 서술한다.

- [[총수익률과 배당수익률]] — `totalReturn`과 `dividendYield`를 더하지 않는다
- [[현금 배당과 재투자 배당]] — 현금으로 나오는 배당과 자산에 남는 배당을 구분한다
- [[원장 불변식]] — 모든 자금 이동은 보존식을 깨지 않는다
- [[HARD와 SOFT 목표]] — 사용자가 확정한 금액만 HARD 제약이 된다
- [[명목가치와 실질가치]] — 단위와 가치 기준을 한 경로에서 섞지 않는다
- [[도달 가능성 5단계]] — 엔진에 코드가 있다고 제품 기능인 것은 아니다
- [[세법 프로필 단일 진실원]] — 세율·한도는 `taxLawProfiles.ts`가 유일한 소스다
- [[잉여 현금 버킷]] — 잉여 현금은 현금 버킷에 남고 첫 번째 자산에 재투자되지 않는다
- [[사적연금 과세와 연말정산]] — 연말 정산액은 pensionTaxPaid에 이미 포함되어 이중 계상하지 않는다. 법정 연금수령한도는 계좌별로 미판정이다
- [[국민연금 과세 오차]] — 납입 이력이 없어 전액 과세하며, 이것이 이 모델의 최대 오차원이다
- [[건강보험료와 피부양자]] — 예상 건강보험료와 피부양자 판정용 소득을 분리하고, 재산 입력 없이 자격 유지를 확정하지 않는다
- [[평가 파이프라인 순서]] — 후보 생성부터 페르소나 추천까지 8단계 순서를 임의로 뒤집지 않는다
- [[후보 생성 축]] — 자동 후보 축은 은퇴 나이·국민연금 개시·인출 정책·소비 패턴 넷뿐이다
- [[조기 국민연금 추천 자격]] — 정상안이 은퇴 직후 공백을 메우면 조기수령을 추천하지 않는다
- [[추천 페르소나 배정]] — 세 카드는 「더 나은 안」이 아니라 「각 기준의 1등」이고, 3개보다 적을 수 있다
- [[대표 추천 선정]] — ☆은 목표를 가장 적게 놓친 안을 먼저 보고, 확률만으로 고르지 않는다
- [[현상 유지 비교 기준]] — 「전」은 같은 경로로 돌린 현상 유지 후보의 원장이고, 없으면 비교를 내지 않는다
