# 건강보험료와 피부양자

## 한 줄 정의

실제 현금흐름의 예상 건강보험료와 피부양자 자격 위험 판정용 소득은 별도 값이며, 재산 입력이
없는 동안 자격 «유지»는 확정하지 않는다.

## 계약

- 건강보험료·의료비 추정은 현행 도메인 모델을 사용하며 임의 상수나 중복 계산식을 UI에
  만들지 않는다.
- 실제 현금흐름의 예상 건강보험료(`healthInsurancePaid`, 문턱 초과분에만 요율을 곱한 값)와
  피부양자 자격 위험 판정용 소득(`healthInsuranceDependentAssessment.income`)을 분리한다.
  세후 국민연금 실수령액을 피부양자 판정용 연금소득으로 재사용하지 않는다.
- 재산 입력이 없는 동안 피부양자 자격 «유지»는 확정하지 않는다. 소득 기준을 넘으면 소득
  사유 탈락(`eligible: false`)은 판정하지만, 기준 이하여도 `eligible: null`이며 「유지」로
  단정하지 않는다.

`status: enforced`인 이유는 위 세 문장이 모두 부정형 계약(「~하지 않는다」)이고, 코드가
그 금지를 어길 수 있는 경로 자체를 갖고 있지 않기 때문이다.
`assessHealthInsuranceDependent()`는 재산 정보를 받는 파라미터가 아예 없어 `eligible: true`를
반환하는 코드 경로가 존재하지 않는다. 두 소득은 `SimulationEngine.ts`에서 애초에 다른
변수(`healthInsurancePaid`는 실제 징수액, `healthInsuranceDependentAssessment.income`은
`healthInsuranceIncomeBasis`)로 계산돼 값을 헷갈릴 표면이 없다. 이 값은 매 시뮬레이션
연도마다 계산되어 `computeRiskAlerts.ts`의 「피부양자 자격 위험」 경고와
`ExpertDetailsPanel.tsx`의 고지 문구까지 실제로 연결돼 있다 — 재산 입력이 없다는 한계는
느슨한 구현이 아니라, 그 한계를 사용자에게 정직하게 전달하는 것 자체가 계약이다.

## 흔한 위반

기록된 사고 없음. 이 계약이 막으려는 실패의 모양은 두 가지다. 하나는 세후 국민연금
실수령액이나 `healthInsurancePaid`를 피부양자 판정 소득으로 재사용해, 보험료가 0원인
해에 자격 위험도 없다고 잘못 결론짓는 것(`RiskAlertCards`의 「예상 건강보험료가 0원이더라도
… 모순이 아닙니다」 문구가 이 실패를 막기 위한 것이다). 다른 하나는 재산 입력 없이
`eligible: true`를 반환하거나 화면에 「자격 유지 확정」처럼 표시하는 것이다.
