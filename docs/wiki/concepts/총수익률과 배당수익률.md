# 총수익률과 배당수익률

## 한 줄 정의

`totalReturn`은 배당을 포함한 총수익률이고, `dividendYield`는 그 안에 들어 있는 분배 성분이다.

## 계약

- **두 값을 더하지 않는다.** 더하면 배당이 이중 계상된다.
- ETF별 프리셋 입력도 일괄 입력과 같은 배당 비율 조정 규칙을 사용한다. 조회 버튼은
  일회성 추정치를 채우며 저장된 출처나 자동 갱신 설정을 만들지 않는다.
- 가격상승률은 `totalReturn − dividendYield`이며, 이 분해가 일어나는 **유일한 자리**는
  `priceGrowthRate()`다. 엔진의 일반자산·ISA 초기화와 화면의 파생값 표시가 모두 이 함수를
  거친다. 두 곳이 각자 빼기를 하면 반올림·클램프 규칙이 갈라져, 화면이 말하는 가격상승률과
  엔진이 쓰는 가격상승률이 달라진다.
- 단위는 둘 다 퍼센트 수치다(7% → `7`). 소수(`0.07`)가 아니다.
- 배당률이 총수익률보다 크면 **음수를 그대로 돌려준다.** 0으로 자르지 않는다. 분배금이
  총수익률을 넘는 만큼 NAV가 줄어드는 상품(커버드콜, 일부 고배당 ETF)이 실제로 존재한다.
  자산이 음수로 발산하는 것은 엔진의 `toMonthlyCompoundRate`가 연 −100% 아래를 막는다.
- **사적연금은 이 분해를 쓰지 않는다.** 연금 계좌 안에는 배당세도 재투자 선택지도 없어
  총수익률만이 결과를 결정하고, 엔진의 두 월율 규약(성장은 기하 복리, 배당은 단리)이 달라
  분해하면 의미 변경을 넘어 산술까지 바뀐다.

## 흔한 위반

- `totalReturn + dividendYield`로 기대수익을 만든다 → 배당 이중 계상.
- 화면이나 PDF가 자체적으로 빼기를 해서 가격상승률을 표시한다 → 엔진과 다른 값을 보여준다.
- 사적연금 총수익률을 배당분으로 분해해 현금 배당소득으로 잡는다 → [[현금 배당과 재투자 배당]]
  위반이기도 하다.
