# 스키마 — LLM Wiki 생성 규칙

이 문서는 `docs/wiki/` 아래 노트를 만들 때 따르는 규칙이다. `src/tests/docs/wikiIntegrity.test.ts`가
이 규칙 중 기계로 확인 가능한 부분을 강제한다.

## 폴더

| 경로 | 담는 것 |
| --- | --- |
| `docs/wiki/concepts/` | 도메인·계산 개념. 시점과 무관하게 현재 계약을 서술한다 |
| `docs/wiki/decisions/` | ADR. 특정 시점의 결정과 그 이유를 서술한다 |

raw 자료(`AGENTS.md`, `docs/PRD.md`, `docs/superpowers/**`, `docs/releases/**`,
`docs/known-issues.md`)는 제자리에 둔다. 옮기지 않는다.

## 파일명

한글로 쓴다. 사용자가 Obsidian에서 직접 읽고 링크를 타는 것이 목적이므로 영문 슬러그 +
`title` 프런트매터 방식은 쓰지 않는다.

- 개념 노트: 개념 이름 그대로. 띄어쓰기 허용. 예 `concepts/총수익률과 배당수익률.md`
- ADR: `YYYY-MM-DD-` + 한글 제목. 예 `decisions/2026-08-19-수익률 입력을 총수익률로 통일.md`

날짜 접두사를 ADR에만 두는 이유는, 결정은 시점이 의미를 가지지만 개념은 시점과 무관하게 현재
계약을 서술하기 때문이다.

## 프런트매터 문법

지원하는 문법은 아래 세 가지뿐이다. 저장소에 YAML 파서가 없어 최소 문법만 직접 파싱한다.

```yaml
---
key: 스칼라값
inline: [값1, 값2]
quoted: ["따옴표 안에는 쉼표, 도 들어간다", "값2"]
block:
  - 값1
  - 값2
---
```

- 값의 앞뒤 큰따옴표·작은따옴표는 벗겨진다.
- 중첩 매핑, 여러 줄 문자열, 앵커는 지원하지 않는다. 쓰지 않는다.

## 개념 노트

```markdown
---
type: concept
status: enforced
sources: ["[[AGENTS]] 금융 및 계산 원칙", "[[PRD]] §8.3"]
code: [src/core/usecases/returns/decomposeReturn.ts]
tests: [src/tests/core/usecases/SimulationEngine.totalReturn.test.ts]
tags: [계산계약, 배당]
---
# 개념 이름

## 한 줄 정의
## 계약
## 흔한 위반
## 근거
## 관련
```

필드 규칙:

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| `type` | 예 | `concept` 고정 |
| `status` | 예 | `enforced` \| `partial` \| `not-implemented` |
| `sources` | 예 | 최소 1개. 각 값은 `[[링크]]`를 포함한다 |
| `code` | 아니오 | repo 루트 기준 상대 경로. 실존해야 한다 |
| `tests` | `status: enforced`면 예 | repo 루트 기준 상대 경로. 실존해야 한다 |
| `tags` | 아니오 | 자유 |

`status` 의미:

- `enforced` — 계약이 production 경로에서 실제로 지켜지고, 그것을 지키는 테스트가 있다.
- `partial` — 코드에 있으나 현행 production 입력·경로에서 완전히 성립하지는 않는다.
  예: 소득세법 시행령 제40조의2 연금수령한도는 공식이 core에 있으나 연금수령 기산연도 입력이
  없어 계좌별 준수 여부가 `미판정`이다.
- `not-implemented` — 계약만 정의돼 있고 구현이 없다.

이 구분은 `AGENTS.md` 문서 현행화 원칙의 "구현된 기능, 제한적 기능, 미구현 기능을 구분한다"를
노트 단위로 강제하기 위한 것이다. 코드에 타입이나 함수가 있다는 이유만으로 `enforced`로 적지
않는다.

섹션 규칙:

- `## 한 줄 정의` — 한 문장.
- `## 계약` — 지켜야 할 규칙. 원자료 문장을 근거로 쓴다. **창작하지 않는다.**
- `## 흔한 위반` — 실제로 났던 실수. 없으면 섹션을 비우지 말고 노트를 만들 이유를 다시 본다.
- `## 근거` — 코드 경로와 테스트. 프런트매터의 `code`·`tests`와 일치시킨다.
- `## 관련` — 다른 개념 노트와 ADR을 `[[링크]]`로 건다. 최소 1건.

## ADR

```markdown
---
type: decision
decided: 2026-08-19
source: "[[2026-08-19-total-return-unification-design]]"
affects: ["[[총수익률과 배당수익률]]"]
---
# 결정 제목

## 결정
## 배경
## 기각한 대안
## 호환성 처리
## 영향받는 개념
```

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| `type` | 예 | `decision` 고정 |
| `decided` | 예 | `YYYY-MM-DD` |
| `source` | 예 | `[[링크]]`를 포함한다. 근거가 된 spec 문서 |
| `affects` | 아니오 | 각 값은 `[[링크]]`를 포함한다 |

## 링크

`[[노트 이름]]` 형식을 쓴다. Obsidian은 보관함 안 파일을 basename으로 해석하므로 확장자와
경로를 적지 않는다. `[[노트 이름|표시 텍스트]]`와 `[[노트 이름#섹션]]`도 허용한다.

링크 대상은 보관함(= repo 루트) 안의 마크다운 파일이어야 한다. 없는 대상을 가리키면 무결성
테스트가 실패한다.

## 갱신 규칙

- 계산 계약·도메인 규칙을 바꾸면 해당 개념 노트를 **같은 커밋에서** 갱신한다.
- 새 설계 결정을 확정하면 `decisions/`에 ADR을 남긴다.
- 노트를 새로 만들면 `색인.md`에 한 줄 추가한다.
