# NextLife PRD (Product Requirements Document)

- **Version**: 4.0
- **Status**: 현행 production 구현 기준
- **Last Updated**: 2026-08-25

---

## 1. 제품 개요

NextLife는 사용자의 현재 자산·연금·기타소득과 최대 5개의 은퇴 목표를 바탕으로 여러 은퇴
전략을 자동 생성·평가하는 목표 기반 은퇴 설계 서비스다. 월 단위 결정론적 시뮬레이션과 Monte
Carlo 검증을 결합해 현재 계획의 지속 가능성을 보여 주고 안정형·균형형·여유형 전략을 추천한다.

NextLife는 투자 권유나 미래 수익 보장 서비스가 아니다. 세금, 건강보험료, 수익률, 변동성은
프로젝트에 정의된 단순화 모델과 사용자 입력에 따른 추정치다.

## 2. 제품 목표

사용자는 다음 질문에 답을 얻을 수 있어야 한다.

1. 현재 계획으로 목표 생활비와 선택한 은퇴 목표를 얼마나 달성할 수 있는가?
2. 자산 고갈 위험과 기대수명 시점의 잔여 자산은 어느 정도인가?
3. 수익률 순서가 불리해져도 계획이 견딜 확률은 어느 정도인가?
4. 은퇴 나이, 국민연금 개시 시점, 계좌 인출 순서, 소비 패턴을 어떻게 조정하면 나아지는가?
5. 안정성, 목표 균형, 은퇴 초반의 여유 중 무엇을 우선한 전략이 적합한가?

사용자가 저수준 전략 설정을 모두 직접 결정하지 않아도 비교 가능한 추천을 얻는 것이 핵심이다.
기존 상세 설정은 호환성을 위해 유지하되 자동 최적화 엔진의 입력으로 점진적으로 흡수한다.

## 3. 사용자 흐름

```text
1. 개인정보 입력
   - 현재 나이, 기대수명
2. 자산정보 입력
   - 일반 투자자산, ISA, 국민연금, 사적연금, 기타소득
3. 은퇴 목표 선택
   - 1~5개, 우선순위, HARD/SOFT
4. 분석 시작
5. 현재 계획 시뮬레이션
6. 전략 후보 자동 생성·목표 평가
7. 상위 후보 Monte Carlo 검증
8. 안정형·균형형·여유형 추천과 상세 결과 확인
```

분석은 사용자가 `분석 시작`을 선택한 뒤 실행한다. 입력 중 매 변경마다 전체 최적화를 자동으로
재실행하지 않는다.

## 4. 사용자·시나리오·보안

### 4.1 계정

- 이메일 가입 후 발급된 6자리 보안키로 로그인한다.
- 이메일과 보안키 외의 소셜 로그인은 현행 범위가 아니다.
- 보안키 초기화 후 새 키로 로그인하면 기존 암호화 시나리오는 복구할 수 없고 삭제된다.
- 개발 자동 로그인은 production에서 도달할 수 없어야 한다.

### 4.2 저장과 암호화

- 사용자당 시나리오는 최대 5개다.
- 시나리오 평문은 브라우저에서 암호화·복호화하며 서버에는 E2EE 암호문만 저장한다.
- E2EE 잠금 계정에 평문 시나리오 업데이트를 허용하지 않는다.
- 기존 버전 데이터는 migration·normalizer·adapter를 통해 읽을 수 있어야 한다.

### 4.3 실행 위치

- 결정론적 시뮬레이션, 목표 평가, 전략 최적화는 브라우저에서 수행한다.
- 반복량이 큰 Monte Carlo와 전략 최적화는 Web Worker를 사용해 UI 정지를 줄인다.
- Worker와 메인 스레드는 같은 core 도메인·계산 코드를 사용해야 한다.

## 5. 입력 요구사항

### 5.1 개인정보

- `currentAge`: 시뮬레이션 기준 나이
- `expectancy`: 시뮬레이션 종료 나이

은퇴 나이는 고정 개인정보가 아니라 현재 계획과 전략 후보가 바꿀 수 있는 설계 변수다. 배우자·
가족 정보 및 근로소득 입력은 현행 production 입력 범위에 포함되지 않는다.

### 5.2 투자·연금·소득

- 일반 투자자산과 ISA: 이름/식별자, 통화, 보유 가치 구성, 월 적립액, `totalReturn`,
  `dividendYield`, 일반계좌 배당 재투자 여부 등 현행 도메인 필드
- 국민연금: 예상 월 수령액과 개시 나이
- 사적연금: 유형, 통화, 잔액, 월 적립액, 총수익률, 인출 관련 현행 설정
- 기타소득: 이름, 월 금액, 통화 및 현행 기간 설정
- 공통: KRW/USD 자산과 표시 통화, 기준 환율, 인플레이션·시장 시나리오 등 기존 상세 설정

`totalReturn`은 배당을 포함한 연 총수익률이다. `dividendYield`는 총수익 중 분배되는 성분이므로
별도 성장률처럼 다시 더하지 않는다.

## 6. 은퇴 목표

사용자는 아래 목표 중 최소 1개, 최대 5개를 선택한다.

| 목표 | 의미 |
|---|---|
| 생활비 안정 | 목표 생활비 충당의 지속성 |
| 빠른 은퇴 | 사용자가 원하는 은퇴 나이 달성 |
| 자산 고갈 방지 | 기대수명 전 자산 고갈 방지 |
| 여유 있는 소비 | 더 높은 은퇴 소비 수준 확보 |
| 주거 안정 | 주거 관련 안정성 반영 |
| 연금 최대 활용 | 연금 개시·활용 전략 개선 |
| 세금 최소화 | 세금 부담이 낮은 경로 선호 |
| 투자 위험 최소화 | 하방 위험과 변동성 축소 |
| 상속 자산 확보 | 기대수명 시점 목표 자산 확보 |
| 자산 성장 | 장기 자산 성장 선호 |

각 목표는 우선순위와 `HARD` 또는 `SOFT` 제약을 가진다. 금액형 HARD 목표는 사용자가 목표액을
명시적으로 확정한 경우에만 후보 제거 조건으로 사용한다. 시스템이 미리 채운 값은 제안이며
사용자 확정값으로 간주하지 않는다.

## 7. 전략 생성·평가·추천

### 7.1 후보 생성

현재 계획을 항상 기준 후보로 포함하고 다음 축을 조합한다.

- 은퇴 나이: 허용 범위 내 58~65세 그리드, 현재 설정과 목표 나이를 포함
- 국민연금 개시 나이: 60·65·70세 중 현재 나이와 시뮬레이션 기간에 유효한 값
- 계좌 인출 정책: `GENERAL_FIRST`, `ISA_FIRST`, `PENSION_FIRST`, `TAX_OPTIMIZED`
- 소비 패턴: `FIXED`, `FRONT_LOADED`, `CARE_HEAVY`

관련 계좌가 없으면 해당 인출 축을 불필요하게 확장하지 않는다. 기본 후보 상한은 1,000개다.

사적연금 개시 나이, 현금 버퍼 개월 수, 동적 가드레일, `max_sustainable` 소비 모드는 현행 자동
탐색 축이 아니다. 코드나 저장 데이터에 흔적이 있어도 production 추천 기능으로 표기하지 않는다.

### 7.2 평가 파이프라인

```text
후보 생성
  → 시뮬레이션 전 HARD 조건 제거
  → 결정론적 월 단위 시뮬레이션
  → 목표별 달성도 평가
  → 시뮬레이션 후 HARD 조건 제거
  → 결정론적 순위화
  → 상위 후보 Monte Carlo 검증
  → 페르소나별 추천
```

- 결정론적 shortlist 기본값은 12개다.
- Monte Carlo screening은 기본 200회이며 최종 표시 후보는 1,000회로 검증한다.
- 최종 후보는 최대 3개이고 고정 시드를 사용해 같은 입력의 재현성을 유지한다.
- 포트폴리오 가중 총수익률에서 변동성을 추정하되 프로젝트의 10~20%p 앵커 범위 안에서
  사용한다. 이는 과거 수익률 부트스트랩이나 시장 예측 모델이 아니다.

### 7.3 추천 페르소나

- **안정형**: 자산 생존 확률, 하위 10% 잔여 자산, 생활비 성공률을 우선한다.
- **균형형**: 목표 성공 확률, 가중 목표 점수, 생활비 성공률의 균형을 우선한다.
- **여유형**: `FRONT_LOADED` 소비 후보 중 생활비와 목표 달성 가능성을 우선한다.

조건을 충족하는 서로 다른 후보가 부족하면 추천 카드가 3개보다 적을 수 있다. 대표 추천은
우선순위 가중 미달 목표가 적은 후보를 먼저 보고 목표 성공 확률과 가중 점수로 순위를 정한다.

## 8. 시뮬레이션 엔진 계약

### 8.1 시간·단위·가치 기준

- 현재 나이부터 기대수명까지 월 단위로 계산하고 연도별 결과를 집계한다.
- 나이와 달력 연도를 구분한다.
- 내부 금액 단위와 기준 통화를 통일하고 원·만원·억원 표시는 UI/PDF에서만 변환한다.
- 명목·실질 모드를 한 경로에서 혼용하지 않는다.

### 8.2 축적기와 은퇴기

- 은퇴 전에는 현행 설정에 따라 투자·연금 적립과 복리 수익을 반영한다.
- 은퇴 후에는 정기 적립을 중단하고 연금·기타소득·현금 배당·자산 인출로 지출을 충당한다.
- 부족분은 선택된 계좌 인출 정책과 기존 호환 경로에 따라 충당한다.
- 소득과 인출이 지출을 초과한 잉여액은 현금 버킷에 남아 `cashAssets`에 포함된다. 첫 번째
  투자자산으로 강제 재투자하지 않는다.

### 8.3 배당

- 일반계좌에서 `reinvestDividend=false`인 배당은 세후 현금으로 지급되어 `dividendIncome`과
  생활비 충당 소득에 포함된다.
- 일반계좌에서 `reinvestDividend=true`인 배당은 은퇴 후에도 자산 내부에 남으며 현금소득으로
  잡지 않는다.
- ISA 배당은 계좌 내부에 유보·재투자되며 현금 배당소득으로 잡지 않는다.
- 사적연금은 총수익률로 성장하며 그 수익을 별도 현금 배당으로 분해하지 않는다.
- 대시보드와 PDF는 사용 가능한 현금 배당과 자산에 남은 재투자 배당을 명확히 구분한다.

### 8.4 인출·세금·건강보험료

- 일반자산 매도는 가중평균 원가를 사용해 원금과 실현이익을 분리한다.
- 일반계좌·ISA·사적연금의 세금과 인출 규칙은 중앙 세법 프로필과 계좌 엔진을 사용한다.
- 현행 세법 프로필은 2024년 기준의 단순화 모델이며 법률·세무 자문을 대신하지 않는다.
- 사적연금 저율과세 한도 기본값은 연 15,000,000원이며 종합소득세 구간 등은
  `src/core/usecases/tax/taxLawProfiles.ts`를 Single Source of Truth로 한다.
- 건강보험료와 의료비 추정은 현행 도메인 모델을 사용하며 임의 상수나 중복 계산식을 UI에 만들지
  않는다.
- 실제 현금흐름의 예상 건강보험료와 피부양자 자격 위험 판정용 소득을 분리한다. 세후 국민연금
  실수령액을 피부양자 판정용 연금소득으로 재사용하지 않는다. 재산 입력이 없는 동안 자격 유지를
  확정하지 않는다.
- 사적연금은 계좌별로 기초잔액·납입·이전·운용수익·순인출·세금·기말잔액 원장을 남기며,
  계좌 합계가 사적연금 자산군 총액과 일치해야 한다.
- 연 15,000,000원 저율과세 기준과 소득세법 시행령 제40조의2의 연금수령한도는 별도 개념이다.
  법정 연금수령한도 공식은 core에 유지하되, 현행 production 입력에는 연금수령 기산연도·과세기간
  개시일 평가액·2013년 이전 가입 예외가 없으므로 실제 계좌별 준수 여부는 `미판정`으로 표시한다.
  기대수명 균등분할액이나 저율과세 기준을 법정 한도로 대신 사용하지 않는다.

### 8.5 원장 불변식

모든 자금 이동은 다음 보존 관계를 깨지 않아야 한다.

```text
기말자산 = 기초자산 + 외부유입 + 투자손익 - 생활비 - 세금 - 건강보험료 - 기타외부유출
```

현금 배당, 재투자 배당, 매도 원금, 실현이익, 연금 인출, 세금은 중복 계상하거나 누락하지 않는다.
생활비 목표는 국민연금·사적연금·현금배당·기타소득·자산인출·부족액의 합과 일치해야 하며,
자산군 합계는 총자산 추이와 일치해야 한다.

## 9. 결과와 리포트

### 9.1 현재 계획 분석

- 목표별 달성 상태와 종합 점수
- 생활비 충당률·성공 기간
- 자산 고갈 여부와 고갈 시점
- 기대수명 시점 잔여 자산
- 연도별 자산·현금흐름·세금·건강보험료
- 순서 리스크 및 Monte Carlo 시뮬레이션 성공률·분포. 순서 리스크는 은퇴 전 경로를 고정하고
  은퇴 후 동일 수익률 집합의 순서만 비교한다.

### 9.2 추천 비교

- 안정형·균형형·여유형별 핵심 변경점과 선택 이유
- 현재 계획 대비 목표 점수, 확률, 소비, 잔여 자산의 차이
- 추천 전략의 은퇴 나이, 연금 개시, 인출 정책, 소비 패턴
- HARD 목표 미달 또는 추천 불가 이유

### 9.3 대시보드와 PDF 일관성

- UI와 PDF는 같은 엔진 결과와 공용 파생 계산을 사용한다.
- 현금 배당소득은 생활비 재원으로, 재투자 배당은 자산 내부 증가분으로 구분해 표시한다.
- 명목/실질, 기준 통화, 세전/세후 라벨을 생략하거나 혼용하지 않는다.
- **지표가 무엇을 판정했는지 서술하는 문구는 core에 한 벌만 둔다.** 화면과 PDF가 같은
  문장을 인쇄해야 하고, 그 서술의 근거(판정 술어·기준 금액·실행 가정)는 엔진의 것이기
  때문이다. 현재 이 규약을 따르는 문구는 몬테카를로 가정 공시
  (`describeMonteCarloAssumptions`), 두 성공률의 기준(`describeSuccessRates`), 지속 가능한
  한도의 기준(`describeSustainableSpendingBasis`), 민감도 수익률 축의 앵커
  (`describeYieldAxisAnchors`)다.
- 지표 옆에는 그 값이 «어느 실행에서 나왔는지»를 함께 밝힌다. 결정론 단일 경로의 값과
  시장 변동 시행의 값을 기준 표시 없이 나란히 놓지 않는다.

## 10. AI 설명 기능

Ollama 연동이 설정된 경우 분석 결과에 대한 설명 문구를 생성할 수 있다. 호출 실패나 미설정 시
규칙 기반 문구로 대체한다. LLM은 금융 계산, 목표 판정, 후보 생성, 순위화, Monte Carlo 결과를
변경할 권한이 없다. 대화형 투자 코치는 현행 범위가 아니다.

## 11. 비기능 요구사항

- core 계산 계층은 UI·DB 프레임워크에 의존하지 않는다.
- TypeScript strict 계약을 유지하고 계산 경로의 `any` 사용을 피한다.
- 동일 입력과 고정 시드는 재현 가능한 결과를 내야 한다.
- 신규 계산에는 unit test, 오류 수정에는 regression test를 추가한다.
- 기존 API와 저장 데이터 변경 시 migration 또는 adapter를 먼저 제공한다.
- 결과에는 투자 권유가 아니며 실제 미래를 보장하지 않는다는 면책을 표시한다.

## 12. 현행 제한사항과 후속 범위

- 배우자·가족 단위 프로필과 유족연금 입력 흐름은 production에 연결되어 있지 않다.
- 근로소득·저축률을 별도 모델링하는 입력 흐름은 없다. 자산별 월 적립액을 사용한다.
- 사적연금 독립 개시 나이, 현금 버퍼, 동적 가드레일, `max_sustainable`는 자동 후보 축이 아니다.
- Monte Carlo 변동성은 프로젝트 앵커 기반 추정이며 실제 자산별 역사 데이터 모델이 아니다.
- 세금·건강보험료 모델은 단순화되어 있으며 제도 변경을 자동 반영하지 않는다.
- 추천 결과는 입력과 모델 가정의 비교 결과이며 개인화된 투자·세무·법률 자문이 아니다.

후속 기능은 별도 단계에서 명시적으로 승인된 경우에만 구현하며, 타입이나 미사용 엔진 코드가
존재한다는 이유로 현행 지원 범위를 확대하지 않는다.

## 13. 인수 기준

1. 사용자가 1~5개 목표를 저장하고 분석을 시작할 수 있다.
2. 현재 계획이 기준 후보로 평가되고 지원되는 전략 축에서 대안이 생성된다.
3. 사용자 확정 HARD 목표만 후보 제거 조건으로 동작한다.
4. 동일 입력의 결정론적 결과와 고정 시드 Monte Carlo 결과가 재현된다.
5. 추천 카드가 페르소나 기준을 따르고, 후보 부족 시 과장된 대체 카드를 만들지 않는다.
6. 현금 배당과 재투자 배당이 계산·대시보드·PDF에서 같은 의미로 구분된다.
7. 총자산 보존식과 세금·인출 회귀 테스트가 통과한다.
8. 기존 저장 시나리오가 migration·adapter를 거쳐 동일 의미로 로드된다.
9. 서버가 E2EE 시나리오 평문을 요구하거나 저장하지 않는다.
