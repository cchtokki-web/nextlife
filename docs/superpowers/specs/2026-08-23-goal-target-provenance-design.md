# 시스템이 깔아 준 숫자를 사용자가 정한 숫자로 취급하지 않는다

`known-issues` 2번의 설계. 승인 지시(2026-08-23)를 그대로 옮긴다:

> 시스템이 제공한 seed를 사용자가 확정한 목표금액으로 취급하지 마세요. 추천/초기값과 사용자가
> 확정한 값을 의미적으로 분리하고, 사용자가 확인하지 않은 숫자가 shortfall이나 HARD/SOFT
> 실패를 «영구적으로» 발생시키지 않도록 합니다. 체감 커브 역시 확정된 목표금액이 있을 때
> 그것을 기준으로 파생합니다.

## 선결 조사 결과 — 기존 데이터는 «구별할 수 없다»

지시대로 먼저 조사했다. **구별 불가다.**

```ts
interface RetirementGoal {
  type: RetirementGoalType;
  priority: number;
  targetValue?: number;      // ← 씨앗과 사용자 입력이 같은 자리에 같은 형태로 저장된다
  constraintType: RetirementGoalConstraintType;
}
```

`RetirementGoalSelector.toggleGoal`이 목표를 고르는 «순간» `targetValue: defaultTarget(type)`을
써넣고(`LIVING_EXPENSE_STABILITY`·`COMFORTABLE_SPENDING`은 계획의 `targetMonthlySpending`,
`INHERITANCE`는 `targetBequest ?? targetMonthlySpending * 24`), 사용자가 그 뒤에 고쳤는지는
아무데도 남지 않는다. 편집 경로(`updateGoal`)는 «분리되어» 있으므로 앞으로는 표시할 수 있지만,
**이미 저장된 값의 출처는 복원할 방법이 없다.**

따라서 지시의 이 문장이 그대로 적용된다:

> 구분할 수 없는 데이터를 임의로 사용자 확정값으로 간주하지 마세요.

## 설계

### 출처를 표시한다 — «없음»이 기본이다

`RetirementGoal`에 출처 표시를 «선택 필드»로 더한다. 값이 «없으면 미확정»이다.

기본값을 「미확정」 쪽에 두는 것이 핵심이다. 필수 필드로 만들거나 기본값을 「확정」으로 두면
기존 저장 데이터가 «전부» 확정으로 승격되는데, 그것이 지시가 금지한 바로 그 일이다.
마이그레이션은 «하지 않는다» — 표시가 없는 것이 곧 「모른다」이고, 모르는 것은 미확정이다.

- `toggleGoal`이 깔아 주는 씨앗에는 표시를 «붙이지 않는다».
- `updateGoal`을 통해 사용자가 «직접 입력»한 값에만 표시를 붙인다.

### 미확정 값은 실패를 만들지 않는다

미확정 `targetValue`는 **shortfall 계산과 HARD/SOFT 판정에 참여하지 않는다.**
계획의 다른 축(예: 계획 자체의 목표 생활비)은 그대로 쓴다 — 없애는 것은 「사용자가
말한 적 없는 숫자를 근거로 실패를 선언하는 일」뿐이다.

이 규칙이 2번의 증상을 없앤다: 씨앗 350만원이 체감 커브에 0.76배로 눌려 «구조적으로»
영구 미달이 되던 상태가, 애초에 판정 대상이 아니게 된다.

### 체감 커브는 «확정된» 목표에서 파생한다

확정된 목표금액이 있으면 그것을 기준으로 삼는다. 없으면 종전대로 계획의 값을 쓴다.
확정되지 않은 씨앗을 기준으로 커브를 파생하지 않는다 — 그것이 지금 미달을 만드는 경로다.

### 화면은 「아직 제안입니다」를 보여야 한다

미확정 값이 판정에 참여하지 않는다는 것은, 사용자가 「반드시 지키기」를 골라 두고도
그 금액이 강제되지 않는다는 뜻이다. **그 상태를 숨기면 이번 수정이 목표를 조용히 약화시킨다.**

그래서 화면은 그 값이 아직 제안임을, 그리고 확정하려면 무엇을 해야 하는지를 밝혀야 한다.
문구는 구현 단계에서 정하되 **새 숫자를 만들지 않는다** — 제안값 자체는 지금 쓰는 것을 그대로 쓴다.

## 하지 않는 것

- **새 금융 가정·숫자를 만들지 않는다.** 씨앗 규칙(`targetMonthlySpending`,
  `targetBequest ?? targetMonthlySpending * 24`)은 «그대로»다. 바뀌는 것은 그 값의 «지위»뿐이다.
- **기존 데이터를 마이그레이션하지 않는다.** 표시가 없는 것이 곧 미확정이다.
- **씨앗을 없애지 않는다.** 빈 칸으로 두면 사용자가 매번 숫자를 지어내야 한다.
  문제는 씨앗의 «존재»가 아니라 그것이 «확정으로 취급»되는 것이다.
