# HARD는 강도와 «기준»을 «모두» 확정해야 성립한다

`known-issues` 14번의 설계. 승인 지시(2026-08-23)의 원칙:

> **HARD = strength confirmed + measurable criterion confirmed**
> 시스템 seed가 `targetValue > 0`이라는 이유만으로 확정된 것으로 간주하지 않는다.

예시로 주신 상태 — 시스템이 월 350만원을 제안하고 사용자가 「반드시 지키기」를 골랐을 때 —
는 **양쪽 다 하지 않는다.** 350만원을 그대로 강제하지도 않고, HARD를 무효 상태로
통과시키지도 않는다. 사용자에게 그 금액을 «확인하거나 수정하도록» 요구한다.

## 목표별 정량 기준 — `targetValue` 하나로 일반화하지 않는다

지시대로 목표마다 그 목표에 «실제로 정의된» 기준으로 검증한다.

| 목표 | 정량 기준 | 값의 출처 | HARD일 때 확정 필요? |
|---|---|---|---|
| 생활비 안정 | 월 생활비 | **씨앗** (`targetMonthlySpending`) | **예** |
| 여유 있는 소비 | 월 생활비 | **씨앗** (`targetMonthlySpending`) | **예** |
| 상속 | 잔여자산 금액 | **씨앗** (`targetBequest ?? 월생활비×24`) | **예** |
| 빠른 은퇴 | 은퇴 나이 | 1단계에서 «사용자가 입력» | 아니오 |
| 자산 고갈 방지 | 자산 유지 기준 시점 | 1단계의 기대수명(`planHorizonAge`) | 아니오 |
| 주거 안정·연금 최대 활용·세금 최소화·투자 위험 최소화 | **정의된 기준 없음** | — | **HARD 선택 불가**(1번에서 처리됨) |

**아래 두 행이 확정을 요구하지 않는 이유**는 그 숫자가 씨앗이 아니라 «사용자가 1단계에서
직접 넣은 값»이기 때문이다. 확정 요구의 목적은 「사용자가 말한 적 없는 숫자로 실패를
선언하지 않는다」이고, 이미 사용자가 말한 숫자에는 그 문제가 없다.
**새 입력 필드를 만들지 않는다** — 자산 유지 시점을 목표 수준에서 새로 묻지 않는다.

## 「확정」은 «명시적 확인»이다 — 입력 변경이 아니다

지시:

> confirmed는 단순 input focus/change 여부가 아니라 사용자의 «명시적 확인 상태»여야 한다.

**이것은 2번 구현을 바꾼다.** 지금 `targetValueSource: 'user'`는 목표액 입력의 `onChange`에서
찍힌다. 타이핑은 「변경」이지 「확인」이 아니므로, 표시를 찍는 자리를 **명시적 확인 행위**로 옮긴다.

승인된 화면 형태:

```
반드시 지킬 최소 생활비를 확인해 주세요.
월 350만원
[금액 수정]  [이 금액으로 확정]
```

두 갈래 모두 확정으로 끝난다 — 제안된 금액을 그대로 받아들이는 것도, 고쳐서 넣는 것도
사용자의 «행위»다. 다만 **금액을 고치기만 하고 확정하지 않은 상태는 미확정**이다.

## 흐름

- **별도 단계를 만들지 않는다.** 현재 목표 설정 화면 안의 inline confirmation으로 처리한다.
- HARD 목표의 기준이 미확정이면 **다음 단계 진행을 막고 «그 목표 위치»로 안내**한다.
  지금 `RetirementInputFlow`의 사유 문구는 버튼 옆에만 뜨고 목표 카드는 다른 화면에 있어,
  사용자가 둘을 함께 볼 보장이 없다. 어디를 고쳐야 하는지 «가리켜야» 한다.
- **SOFT는 기존 흐름 그대로.** 시스템 추천값을 평가·추천에 쓸 수 있고, 명시적 확정을
  진행 조건으로 요구하지 않는다.

## 기존 데이터

**`targetValue > 0`이라는 이유로 `confirmed = true`로 마이그레이션하지 않는다.**
사용자 확인 여부를 증명할 수 없으면 미확정으로 취급하는 것이 원칙이다(2번과 같은 규칙).

저장된 시나리오가 HARD + 미확정 상태로 로드되면, 그 계획은 «그대로» 열리되 다음 단계로
넘어갈 때 확인을 요구받는다. 저장 데이터를 다시 쓰지 않는다.

## 하지 않는 것

- 새 금융 가정·숫자·입력 필드를 만들지 않는다. 씨앗 규칙은 그대로다.
- 정량 기준이 없는 목표에 기준을 «지어내지» 않는다 — 그 목표들은 HARD가 될 수 없다(1번).
- SOFT 목표에 마찰을 더하지 않는다.
