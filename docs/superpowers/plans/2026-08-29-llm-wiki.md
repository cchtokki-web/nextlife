# LLM Wiki Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** NextLife의 계산 계약과 설계 결정을 Obsidian 보관함의 개념 노트·ADR로 분해하고, 노트가 가리키는 코드·테스트 경로와 `[[링크]]`가 깨지면 `npm test`가 실패하도록 만든다.

**Architecture:** repo 루트를 Obsidian 보관함으로 쓰고, 신규 문서는 `docs/wiki/` 아래에만 만든다. 기존 `AGENTS.md`·`docs/PRD.md`·`docs/superpowers/**`는 raw 자료로 제자리에 둔다. 무결성은 프런트매터 파서(`src/tests/docs/parseWikiNote.ts`)와 vitest 테스트(`src/tests/docs/wikiIntegrity.test.ts`)가 지킨다. 제품 코드는 한 줄도 바뀌지 않는다.

**Tech Stack:** Markdown, Obsidian(순정, 플러그인 없음), TypeScript, vitest 4, `node:fs`. **신규 의존성 없음** — 저장소에 YAML 파서가 없으므로 스키마가 쓰는 최소 문법만 직접 파싱한다.

**Spec:** `docs/superpowers/specs/2026-08-29-llm-wiki-design.md`

**계획에 실린 코드는 2026-08-29에 실제로 실행해 확인했다.** `parseWikiNote.ts`와 그 테스트 5건은 통과하고, `wikiIntegrity.test.ts`는 노트가 없을 때 `노트를 실제로 찾았다` 하나만 실패하며(8건 통과), 골든 샘플 노트를 넣으면 9건 전부 통과한다. 검증에 쓴 임시 파일은 삭제했으므로 Task 2·3에서 새로 만든다.

## Global Constraints

- 제품 코드(`src/core`, `src/web`, `src/app`, `src/infrastructure`)를 수정하지 않는다. 계산 로직 변경 없음.
- 기존 `AGENTS.md`, `docs/PRD.md`, `docs/superpowers/specs`, `docs/superpowers/plans`, `docs/releases`, `docs/known-issues.md`를 이동·삭제하지 않는다. Task 8의 `AGENTS.md` 추가 외에는 내용도 바꾸지 않는다.
- 신규 npm 의존성을 추가하지 않는다.
- 노트 파일명은 한글로 쓴다. 영문 슬러그 + `title` 프런트매터 방식을 쓰지 않는다.
- 위키의 고정 문서 세 개도 한글이다 — `위키 사용법.md`, `스키마.md`, `색인.md`. `README.md`·`index.md`를 쓰지 않는 이유는 2026-08-29 실측이다: `node_modules`에 `README.md`가 532개, `index.md`가 39개 있어 `[[README]]`가 534개 후보와 충돌한다.
- 개념 노트 파일명은 개념 이름 그대로(띄어쓰기 허용), ADR 파일명은 `YYYY-MM-DD-` 접두사 + 한글 제목.
- 노트의 `## 계약` 섹션은 원자료 문장을 근거로 쓴다. 원자료에 없는 규칙을 창작하지 않는다. 원자료와 충돌하면 원자료가 우선이다.
- 프런트매터 `code`·`tests` 값은 repo 루트 기준 상대 경로다. `@/` 별칭이나 절대 경로를 쓰지 않는다.
- `status` 허용값은 `enforced` | `partial` | `not-implemented` 셋뿐이다.
- 매 Task는 `npm test`가 통과하는 상태로 커밋한다.

## 이 계획의 범위

spec §진행 순서의 **0~4단계**를 다룬다. 산출물은 보관함 뼈대, 개념 노트 6개, ADR 3개, 무결성 테스트, `AGENTS.md` 연동이다.

범위 밖:

- **0단계의 Obsidian 설치·보관함 열기는 사용자 작업이다.** 이 계획은 그 방법을 `docs/wiki/위키 사용법.md`에 적는 데까지만 한다(Task 1). 실제 설치는 사용자가 한다.
- **5단계(나머지 개념·ADR 확장)** 는 규칙이 굳은 뒤의 기계적인 작업이라 별도 계획으로 뺀다. 관련 작업을 할 때 그 부분만 채워도 된다.
- **6단계(상시 개발 루프)** 는 산출물이 없다. Task 8의 `AGENTS.md` 항목이 그 루프를 켠다.

## 이 계획이 spec의 진행 순서와 다른 점

spec의 §진행 순서는 무결성 테스트를 4단계(노트를 다 만든 뒤)에 둔다. 이 계획은 **Task 2~3으로 앞당긴다.** 이유는 무결성 테스트가 `스키마.md`의 실행 가능한 형태이기 때문이다. 뒤에 두면 노트 9개를 만든 뒤에야 규칙 위반이 드러나고, 그 시점의 수정 비용은 노트 개수에 비례한다. 앞에 두면 노트를 하나 쓸 때마다 즉시 검증된다.

spec이 4단계에 둔 원래 이유("골든 샘플이 굳은 다음")는 검사 항목을 경로·링크·필수 필드로 제한하는 것으로 대신 충족한다. 파일럿 중 포맷을 바꿔야 하면 `스키마.md`와 무결성 테스트를 **함께** 고친다. spec의 §2단계 검수 지점(Task 4 끝)은 그대로 유지한다.

````markdown
# 스키마 — LLM Wiki 생성 규칙

이 문서는 `docs/wiki/` 아래 노트를 만들 때 따르는 규칙이다. `src/tests/docs/wikiIntegrity.test.ts`가

## 폴더

| 경로 | 담는 것 |
| --- | --- |
| `docs/wiki/concepts/` | 도메인·계산 개념. 시점과 무관하게 현재 계약을 서술한다 |
| `docs/wiki/decisions/` | ADR. 특정 시점의 결정과 그 이유를 서술한다 |

## 파일명

한글로 쓴다. 사용자가 Obsidian에서 직접 읽고 링크를 타는 것이 목적이므로 영문 슬러그 +

- 개념 노트: 개념 이름 그대로. 띄어쓰기 허용. 예 `concepts/총수익률과 배당수익률.md`
- ADR: `YYYY-MM-DD-` + 한글 제목. 예 `decisions/2026-08-19-수익률 입력을 총수익률로 통일.md`

날짜 접두사를 ADR에만 두는 이유는, 결정은 시점이 의미를 가지지만 개념은 시점과 무관하게 현재
계약을 서술하기 때문이다.

## 프런트매터 문법

지원하는 문법은 아래 세 가지뿐이다. 저장소에 YAML 파서가 없어 최소 문법만 직접 파싱한다.

```yaml
---
key: 스칼라값
inline: [값1, 값2]
quoted: ["따옴표 안에는 쉼표, 도 들어간다", "값2"]
block:
  - 값1
  - 값2
---
```

- 값의 앞뒤 큰따옴표·작은따옴표는 벗겨진다.
- 중첩 매핑, 여러 줄 문자열, 앵커는 지원하지 않는다. 쓰지 않는다.

## 개념 노트

```markdown
---
type: concept
status: enforced
sources: ["[[AGENTS]] 금융 및 계산 원칙", "[[PRD]] §8.3"]
code: [src/core/usecases/returns/decomposeReturn.ts]
tests: [src/tests/core/usecases/SimulationEngine.totalReturn.test.ts]
tags: [계산계약, 배당]
---
# 개념 이름

## 한 줄 정의
## 계약
## 흔한 위반
## 근거
## 관련
```

필드 규칙:

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| `type` | 예 | `concept` 고정 |
| `status` | 예 | `enforced` \| `partial` \| `not-implemented` |
| `sources` | 예 | 최소 1개. 각 값은 `[[링크]]`를 포함한다 |
| `code` | 아니오 | repo 루트 기준 상대 경로. 실존해야 한다 |
| `tests` | `status: enforced`면 예 | repo 루트 기준 상대 경로. 실존해야 한다 |
| `tags` | 아니오 | 자유 |

`status` 의미:

- `enforced` — 계약이 production 경로에서 실제로 지켜지고, 그것을 지키는 테스트가 있다.
- `partial` — 코드에 있으나 현행 production 입력·경로에서 완전히 성립하지는 않는다.
  예: 소득세법 시행령 제40조의2 연금수령한도는 공식이 core에 있으나 연금수령 기산연도 입력이
  없어 계좌별 준수 여부가 `미판정`이다.
- `not-implemented` — 계약만 정의돼 있고 구현이 없다.

이 구분은 `AGENTS.md` 문서 현행화 원칙의 "구현된 기능, 제한적 기능, 미구현 기능을 구분한다"를
노트 단위로 강제하기 위한 것이다. 코드에 타입이나 함수가 있다는 이유만으로 `enforced`로 적지
않는다.

섹션 규칙:

- `## 한 줄 정의` — 한 문장.
- `## 계약` — 지켜야 할 규칙. 원자료 문장을 근거로 쓴다. **창작하지 않는다.**
- `## 흔한 위반` — 실제로 났던 실수. 없으면 섹션을 비우지 말고 노트를 만들 이유를 다시 본다.
- `## 근거` — 코드 경로와 테스트. 프런트매터의 `code`·`tests`와 일치시킨다.
- `## 관련` — 다른 개념 노트와 ADR을 `[[링크]]`로 건다. 최소 1건.

## ADR

```markdown
---
type: decision
decided: 2026-08-19
source: "[[2026-08-19-total-return-unification-design]]"

---
# 결정 제목

## 결정
## 배경
## 기각한 대안
## 호환성 처리
## 영향받는 개념
```

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| `type` | 예 | `decision` 고정 |
| `decided` | 예 | `YYYY-MM-DD` |
| `source` | 예 | `[[링크]]`를 포함한다. 근거가 된 spec 문서 |
| `affects` | 아니오 | 각 값은 `[[링크]]`를 포함한다 |

## 링크

`[[노트 이름]]` 형식을 쓴다. Obsidian은 보관함 안 파일을 basename으로 해석하므로 확장자와
경로를 적지 않는다. `[[노트 이름|표시 텍스트]]`와 `[[노트 이름#섹션]]`도 허용한다.

링크 대상은 보관함(= repo 루트) 안의 마크다운 파일이어야 한다. 없는 대상을 가리키면 무결성
테스트가 실패한다.

## 갱신 규칙

- 새 설계 결정을 확정하면 `decisions/`에 ADR을 남긴다.
- 노트를 새로 만들면 `색인.md`에 한 줄 추가한다.
````

````markdown
# LLM Wiki

NextLife의 계산 계약과 설계 결정을 개념 단위로 쪼개 서로 링크로 이은 지식 레이어다.

## 왜 있는가

계약은 `AGENTS.md`에 한 줄로, 그 계약이 사는 코드는 `src/core/**`에, 그것을 지키는 테스트는
`src/tests/**`에 흩어져 있다. 이 셋을 잇는 것이 사람의 기억뿐이라, 작업할 때마다 300줄짜리
PRD와 AGENTS.md를 처음부터 읽고 관련 조각을 스스로 찾아야 했다.

이 위키는 그 사이에 개념 레이어를 넣는다. 개념 하나당 노트 하나를 두고, 노트가 원자료·코드·
테스트·다른 개념을 `[[링크]]`로 가리킨다.

## 어떻게 쓰는가

**작업 시작할 때** — `색인.md`에서 관련 개념 노트를 찾아 읽는다. PRD 전체를 읽는 것보다
빠르고, 노트가 근거 코드와 테스트를 직접 가리킨다.

**작업 중** — 개념 노트의 `## 계약`과 `## 흔한 위반`으로 자가 점검한다.

**작업 끝날 때** — 계약을 바꿨으면 해당 노트를 같은 커밋에서 갱신한다. 새 결정을 내렸으면
`decisions/`에 ADR을 남긴다.

## Obsidian으로 보기

1. [obsidian.md](https://obsidian.md)에서 설치한다.
2. **"폴더를 보관함으로 열기"로 repo 루트를 연다.** "새 보관함 생성"이 아니다.
   `docs/`가 아니라 repo 루트인 이유는, 개념 노트가 `[[AGENTS]]`(repo 루트에 있다) 같은 기존
   원자료를 링크하는데 Obsidian은 보관함 «밖» 파일을 링크 대상으로 인식하지 못하기 때문이다.
3. **설정 → 파일 및 링크 → 제외된 파일에 `node_modules`를 추가한다.** 이 단계를 빼면 위키가
   쓸모없어진다 — `node_modules`에 마크다운이 1,367개 있고 repo의 실제 문서는 48개라, 그래프
   뷰에서 28:1로 묻힌다(2026-08-29 실측).
4. 그래프 뷰(`Cmd+G`)로 연결 구조를 본다. 점이 수십 개면 3번이 먹은 것이고, 수백~수천 개면
   3번을 다시 확인한다. 백링크 패널로 한 개념이 어디서 참조되는지 본다.

플러그인은 필요 없다. 그래프 뷰와 백링크는 순정 기본 기능이다.

`.obsidian/`은 `.gitignore`에 있다. 개인 설정이라 커밋하지 않는다.

**파일명이 한글인 이유**: `제외된 파일` 설정은 검색과 그래프에서 «숨길» 뿐 보관함에서 빼지는
않는다. `README.md`라는 이름을 쓰면 `[[README]]`가 `node_modules`의 532개와 여전히 충돌한다.
그래서 이 위키의 고정 문서는 `위키 사용법`·`스키마`·`색인`이다.

## 규칙

노트를 만들거나 고치기 전에 [[스키마]]를 읽는다.

## 무엇을 보장하고 무엇을 보장하지 않는가

`src/tests/docs/wikiIntegrity.test.ts`가 `npm test`에서 다음을 검사한다.

- 프런트매터의 `code`·`tests` 경로가 실제로 존재한다
- `[[링크]]` 대상이 보관함에서 해석된다
- 필수 필드가 있고 허용값이다
````

```ts
/**
 * `docs/wiki/**` 노트의 프런트매터를 읽는다.
 *
 * **YAML 파서를 쓰지 않는 이유**: 저장소에 YAML 의존성이 없고, 이 위키를 위해 하나 들이는
 * 것은 무결성 검사 하나에 비해 과하다. 대신 `docs/wiki/스키마.md`가 지원 문법을 세 가지로
 * 좁혀 두었고, 이 파서는 딱 그만큼만 읽는다. 스키마에 없는 문법(중첩 매핑, 여러 줄 문자열,
 * 앵커)을 노트에 쓰면 여기서 조용히 무시되므로, 스키마를 넓힐 때 이 파서도 함께 넓혀야 한다.
 *
 * 모든 값을 `string[]`로 정규화한다. 호출부가 스칼라와 배열을 분기하지 않게 하려는 것이다.
 */
export interface ParsedWikiNote {
  frontmatter: Record<string, string[]>;
  body: string;
}

const FRONTMATTER = /^---\r?\n([\s\S]*?)\r?\n---\r?\n?/;

function unquote(value: string): string {
  const trimmed = value.trim();
  const quoted =
    (trimmed.startsWith('"') && trimmed.endsWith('"')) ||
    (trimmed.startsWith("'") && trimmed.endsWith("'"));
  return quoted && trimmed.length >= 2 ? trimmed.slice(1, -1) : trimmed;
}

/**
 * 인라인 배열 `[a, "b, c"]`를 쪼갠다. 따옴표 «안»의 쉼표로는 쪼개지 않는다 —
 * `sources: ["[[AGENTS]] 금융, 계산 원칙"]`처럼 값에 쉼표가 들어가는 경우가 실제로 있다.
 */
function splitInlineList(inner: string): string[] {
  const items: string[] = [];
  let current = '';
  let quote: string | null = null;

  for (const char of inner) {
    if (quote) {
      if (char === quote) quote = null;
      current += char;
    } else if (char === '"' || char === "'") {
      quote = char;
      current += char;
    } else if (char === ',') {
      items.push(current);
      current = '';
    } else {
      current += char;
    }
  }
  items.push(current);

  return items.map(unquote).filter((item) => item.length > 0);
}

export function parseWikiNote(raw: string): ParsedWikiNote {
  const match = FRONTMATTER.exec(raw);
  if (!match) return { frontmatter: {}, body: raw };

  const frontmatter: Record<string, string[]> = {};
  let currentKey: string | null = null;

  for (const line of match[1].split(/\r?\n/)) {
    const blockItem = /^\s+-\s+(.*)$/.exec(line);
    if (blockItem && currentKey) {
      frontmatter[currentKey].push(unquote(blockItem[1]));
      continue;
    }

    const entry = /^([A-Za-z_][\w-]*):\s*(.*)$/.exec(line);
    if (!entry) continue;

    const [, key, rest] = entry;
    currentKey = key;

    const value = rest.trim();
    if (value.length === 0) {
      frontmatter[key] = [];
    } else if (value.startsWith('[') && value.endsWith(']')) {
      frontmatter[key] = splitInlineList(value.slice(1, -1));
    } else {
      frontmatter[key] = [unquote(value)];
    }
  }

  return { frontmatter, body: raw.slice(match[0].length) };
}

/** `[[대상]]`의 대상만 뽑는다. 별칭(`|`)과 섹션(`#`)은 잘라낸다. */
export function extractWikiLinks(text: string): string[] {
  const links: string[] = [];
  for (const match of text.matchAll(/\[\[([^\]]+)\]\]/g)) {
    const target = match[1].split('|')[0].split('#')[0].trim();
    if (target.length > 0) links.push(target);
  }
  return links;
}
```

```ts
import { existsSync, readdirSync, readFileSync, statSync } from 'node:fs';
import { join, relative, resolve } from 'node:path';
import { describe, expect, test } from 'vitest';
import { extractWikiLinks, parseWikiNote } from './parseWikiNote';

/**
 * 위키가 «조용히 낡는 것»을 막는다.
 *
 * 개념 노트는 근거 코드와 테스트를 가리키는데, 그 파일이 옮겨지거나 지워져도 마크다운은
 * 아무 신호를 내지 않는다. 그러면 노트는 없는 코드를 가리킨 채 남고, 그걸 읽은 사람이나
 * 에이전트는 틀린 근거로 판단한다. 여기서 깨뜨려 그 순간에 고치게 한다.
 *
 * **이 테스트가 잡지 못하는 것**: 노트 본문이 코드와 «의미적으로» 어긋나는 것. 배당 규칙이
 * 바뀌었는데 노트 문장만 옛날 그대로여도 통과한다. 그건 AGENTS.md의 갱신 규칙과 사람
 * 검수의 몫이다. 이 파일은 경로와 링크만 본다.
 *
 * **위반을 모아서 한 번에 보고한다.** 노트마다 테스트를 따로 만들면 첫 실패에서 멈춰,
 * 아홉 개를 고치려고 아홉 번 돌려야 한다. 검사 하나가 모든 노트를 훑고 위반 목록을 통째로
 * 내놓는 편이 고치는 쪽에 훨씬 낫다.
 */

const REPO_ROOT = resolve(__dirname, '../../..');
const WIKI_ROOT = join(REPO_ROOT, 'docs/wiki');

/** 보관함 스캔에서 건너뛸 디렉터리. node_modules를 걷다 죽지 않게 하는 것이 주 목적이다. */
const SKIP_DIRS = new Set([
  'node_modules',
  '.git',
  '.next',
  '.claude',
  '.worktrees',
  '.obsidian',
  'coverage',
  'out',
  'build',
]);

function walkMarkdown(dir: string, found: string[] = []): string[] {
  for (const entry of readdirSync(dir)) {
    if (SKIP_DIRS.has(entry)) continue;
    const full = join(dir, entry);
    if (statSync(full).isDirectory()) walkMarkdown(full, found);
    else if (entry.endsWith('.md')) found.push(full);
  }
  return found;
}

interface WikiNoteFile {
  /** repo 루트 기준 상대 경로. 실패 메시지에 그대로 쓴다 */
  path: string;
  kind: 'concept' | 'decision';
  frontmatter: Record<string, string[]>;
  body: string;
}

function loadNotes(): WikiNoteFile[] {
  const notes: WikiNoteFile[] = [];
  for (const kind of ['concept', 'decision'] as const) {
    const dir = join(WIKI_ROOT, kind === 'concept' ? 'concepts' : 'decisions');
    if (!existsSync(dir)) continue;
    for (const file of readdirSync(dir).filter((name) => name.endsWith('.md'))) {
      const full = join(dir, file);
      const { frontmatter, body } = parseWikiNote(readFileSync(full, 'utf8'));
      notes.push({ path: relative(REPO_ROOT, full), kind, frontmatter, body });
    }
  }
  return notes;
}

/** Obsidian은 보관함 안 파일을 basename으로 해석한다. 같은 규칙으로 링크 대상을 모은다. */
function loadLinkTargets(): Set<string> {
  const targets = new Set<string>();
  for (const file of walkMarkdown(REPO_ROOT)) {
    const rel = relative(REPO_ROOT, file);
    targets.add(rel.replace(/\.md$/, ''));
    targets.add(rel.split('/').pop()!.replace(/\.md$/, ''));
  }
  return targets;
}

function noteName(note: WikiNoteFile): string {
  return note.path.split('/').pop()!.replace(/\.md$/, '');
}

const notes = loadNotes();
const concepts = notes.filter((note) => note.kind === 'concept');
const decisions = notes.filter((note) => note.kind === 'decision');
const linkTargets = loadLinkTargets();
const conceptNames = new Set(concepts.map(noteName));

const CONCEPT_SECTIONS = ['## 한 줄 정의', '## 계약', '## 흔한 위반', '## 근거', '## 관련'];
const DECISION_SECTIONS = [
  '## 결정',
  '## 배경',
  '## 기각한 대안',
  '## 호환성 처리',
  '## 영향받는 개념',
];
const STATUSES = ['enforced', 'partial', 'not-implemented'];

/** 대상 노트를 훑어 위반 문자열을 모은다. 통과는 빈 배열이다. */
function collect(
  targets: WikiNoteFile[],
  check: (note: WikiNoteFile, fail: (reason: string) => void) => void,
): string[] {
  const violations: string[] = [];
  for (const note of targets) {
    check(note, (reason) => violations.push(`${note.path}: ${reason}`));
  }
  return violations;
}

describe('위키 무결성', () => {
  /**
   * 파서가 망가지거나 폴더 이름이 바뀌면 `notes`가 빈 배열이 되고, 아래 검사들이 전부
   * 빈 배열을 비교하며 통과한다. 그 «조용한 통과»가 가장 위험하므로 먼저 막는다.
   */
  test('노트를 실제로 찾았다', () => {
    expect(concepts.length).toBeGreaterThan(0);
  });

  test('type이 폴더와 일치한다', () => {
    const violations = collect(notes, (note, fail) => {
      const type = note.frontmatter.type?.[0];
      if (type !== note.kind) fail(`type이 '${type ?? '없음'}'이다. '${note.kind}'여야 한다`);
    });
    expect(violations).toEqual([]);
  });

  test('근거 원자료가 [[링크]]로 적혀 있다', () => {
    const violations = collect(notes, (note, fail) => {
      const field = note.kind === 'concept' ? 'sources' : 'source';
      const values = note.frontmatter[field] ?? [];
      if (values.length === 0) return fail(`${field}가 비어 있다`);
      for (const value of values) {
        if (extractWikiLinks(value).length === 0) fail(`${field}의 "${value}"에 [[링크]]가 없다`);
      }
    });
    expect(violations).toEqual([]);
  });

  test('code·tests 경로가 실존한다', () => {
    const violations = collect(notes, (note, fail) => {
      for (const path of [...(note.frontmatter.code ?? []), ...(note.frontmatter.tests ?? [])]) {
        if (!existsSync(join(REPO_ROOT, path))) fail(`${path}가 없다`);
      }
    });
    expect(violations).toEqual([]);
  });

  test('모든 [[링크]] 대상이 보관함에서 해석된다', () => {
    const violations = collect(notes, (note, fail) => {
      const frontmatterText = Object.values(note.frontmatter).flat().join('\n');
      for (const target of extractWikiLinks(`${frontmatterText}\n${note.body}`)) {
        if (!linkTargets.has(target)) fail(`[[${target}]]를 해석할 수 없다`);
      }
    });
    expect(violations).toEqual([]);
  });

  test('필수 섹션이 모두 있다', () => {
    const violations = collect(notes, (note, fail) => {
      const required = note.kind === 'concept' ? CONCEPT_SECTIONS : DECISION_SECTIONS;
      for (const heading of required) {
        if (!note.body.includes(heading)) fail(`${heading} 섹션이 없다`);
      }
    });
    expect(violations).toEqual([]);
  });

  test('개념 노트의 status가 허용값이고 enforced면 근거 테스트가 있다', () => {
    const violations = collect(concepts, (note, fail) => {
      const status = note.frontmatter.status?.[0];
      if (!status || !STATUSES.includes(status)) return fail(`status가 '${status ?? '없음'}'이다`);
      if (status === 'enforced' && (note.frontmatter.tests ?? []).length === 0) {
        fail('status가 enforced인데 tests가 비어 있다');
      }
    });
    expect(violations).toEqual([]);
  });

    // 개념이 하나뿐인 동안에는 링크할 상대가 없다. 둘 이상일 때만 요구한다.
    if (concepts.length < 2) return;
    const violations = collect(concepts, (note, fail) => {
      const self = noteName(note);
      const linked = extractWikiLinks(note.body).filter(
        (target) => conceptNames.has(target) && target !== self,
      );
      if (linked.length === 0) fail('다른 개념 노트로 가는 링크가 없다');
    });
    expect(violations).toEqual([]);
  });

  test('ADR의 decided가 YYYY-MM-DD이고 파일명 접두사와 일치한다', () => {
    const violations = collect(decisions, (note, fail) => {
      const decided = note.frontmatter.decided?.[0] ?? '';
      if (!/^\d{4}-\d{2}-\d{2}$/.test(decided)) return fail(`decided가 '${decided}'다`);
      if (!noteName(note).startsWith(`${decided}-`)) {
```

````markdown
# 총수익률과 배당수익률

## 한 줄 정의

`totalReturn`은 배당을 포함한 총수익률이고, `dividendYield`는 그 안에 들어 있는 분배 성분이다.

## 계약

- **두 값을 더하지 않는다.** 더하면 배당이 이중 계상된다.
- 가격상승률은 `totalReturn − dividendYield`이며, 이 분해가 일어나는 **유일한 자리**는
  `priceGrowthRate()`다. 엔진의 일반자산·ISA 초기화와 화면의 파생값 표시가 모두 이 함수를
  거친다. 두 곳이 각자 빼기를 하면 반올림·클램프 규칙이 갈라져, 화면이 말하는 가격상승률과
  엔진이 쓰는 가격상승률이 달라진다.
- 단위는 둘 다 퍼센트 수치다(7% → `7`). 소수(`0.07`)가 아니다.
- 배당률이 총수익률보다 크면 **음수를 그대로 돌려준다.** 0으로 자르지 않는다. 분배금이
  총수익률을 넘는 만큼 NAV가 줄어드는 상품(커버드콜, 일부 고배당 ETF)이 실제로 존재한다.
  자산이 음수로 발산하는 것은 엔진의 `toMonthlyCompoundRate`가 연 −100% 아래를 막는다.
- **사적연금은 이 분해를 쓰지 않는다.** 연금 계좌 안에는 배당세도 재투자 선택지도 없어
  총수익률만이 결과를 결정하고, 엔진의 두 월율 규약(성장은 기하 복리, 배당은 단리)이 달라
  분해하면 의미 변경을 넘어 산술까지 바뀐다.

## 흔한 위반

- `totalReturn + dividendYield`로 기대수익을 만든다 → 배당 이중 계상.
- 화면이나 PDF가 자체적으로 빼기를 해서 가격상승률을 표시한다 → 엔진과 다른 값을 보여준다.
- 사적연금 총수익률을 배당분으로 분해해 현금 배당소득으로 잡는다.
````
