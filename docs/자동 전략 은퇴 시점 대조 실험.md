# 자동 전략 은퇴 시점 대조 실험

실험일: 2026-10-29. [32건 추가 조사](자동%20전략%20탐색%2032건%20추가%20조사.md)의 12·22번과 정상 추천 사례 2번을 대상으로 한 조사다. 사용자 기능이나 production 탐색 격자를 변경하지 않았다.

## 방법

고정 시드 `20260829`의 합성 시나리오를 전략 컴파일과 기존 센티널 경로로 변환했다. 실험 전용 `ExpandedRetirementGenerator`는 기존 생성 결과에 은퇴 65세 격자 후보의 나머지 축을 유지한 66~70세 후보만 추가한다. 같은 profile·목표·seed와 `StrategyOptimizer`, HARD 검증, 결정론 평가, 중복 제거, shortlist, 페르소나 선별·확정 흐름을 사용한다. 두 실행의 Monte Carlo 설정은 같은 seed `20260101`, 전체 2,000회, 선별 200회다. 기존 생성 결과와 기준 후보는 보존한다.

```bash
npx vitest run --config vitest.harness.config.ts scripts/harness/retirementAgeComparison.harness.ts
SCENARIO_COUNT=22 SHARD_COUNT=10 SHARD_INDEX=1 HARNESS_OUT=/tmp/nextlife-diagnostics npm run harness:mass
```

비교 하니스 1개 테스트와 진단 하니스 1개 테스트가 통과했다. 두 번째 명령은 시나리오 2·12·22를 실행한다. 하니스에 `duplicateOutcomes`와 `cappedCandidates`를 추가해 기존 최적화 debug 값을 기록했다. 페르소나별 제외 사유는 이 debug 값만으로 추적되지 않는다. 기존·확장 격자의 개별 시뮬레이션 시간이나 기기 메모리는 측정하지 않았다.

## 결과

| 사례 | 기존 격자 | 66~70세 추가 | 관찰 |
|---|---|---|---|
| 2 | 생성·통과 217개, shortlist 12개, 확정 3개 | 생성·통과 352개, 동일 결과 24개 제거, shortlist 12개, 확정 3개 | 확정 추천 후보 중 목표 확률 최고값은 71.95% → 83.15%, 해당 은퇴 나이는 65세 → 68세. 사용자가 3년 더 일하는 조건의 비교다. |
| 12 | 217개 모두 생활비 부족 HARD 사후 탈락 | 추가 135개 모두 조기은퇴 나이 HARD 사전 탈락; 기존 217개도 탈락 | 목표를 유지하는 한 추가 시점은 이 사례에서 후보가 되지 못한다. |
| 22 | 289개 모두 생활비 부족·자산 고갈 방지 HARD 사후 탈락 | 추가 180개를 포함한 469개가 동일한 두 HARD 조건에서 탈락 | 추가한 은퇴 나이만으로 두 조건을 동시에 충족하지 못했다. |

12·22번은 통과 후보가 없어 양쪽 모두 Monte Carlo가 실행되지 않았다. 2번 수치는 각 실행에서 **확정된 추천 후보 중 최고값**이며 전체 가능한 후보의 최적값이나 대표 추천의 확률이라고 단정하지 않는다. 2번에서 추가된 후보는 135개이며 선별 수는 12개로 고정됐고, 두 실행의 shortlist 구성이 달라질 수 있다. 기준 후보는 생성 단계에서 유지됐으나 그 자체가 HARD 조건을 위반하면 평가 단계에서 탈락할 수 있다.

## 해석과 제한

2번은 은퇴를 늦추는 격자 밖 대안을 탐색할 가치가 있을 수 있다는 **한 합성 사례**다. 12·22번은 66~70세 추가만으로 기존 HARD 목표를 충족하지 못한 사례다. 셋만으로 실제 사용자 효과나 최적 격자 범위를 결정할 수 없다. 은퇴 나이 변경은 사용자의 목표와 선호를 바꾸는 실질적인 선택이므로 확률 상승만으로 추천 여부를 정해서는 안 된다.

실험 생성기는 65세 격자 후보를 복제하므로 65세 후보가 없는 프로필에는 추가 후보를 만들지 않는다. seed와 겹치는 나이는 건너뛴다. 이 실험 구현은 production 생성 상한·절단 정책을 확장 격자에 재적용하거나 확장 격자의 `axisSizes`·이론 조합 수를 재계산하지 않는다. 다만 세 사례의 생성 수는 1,000 미만이다. 생산용 구현이나 성능 측정으로 사용할 수 없다.

기존 하니스 진단의 2번은 중복 0개, 생성 상한 절단 0개, shortlist 12개였다. 12·22번은 생존 후보가 없어 중복 제거가 실행되지 않았으므로 기록값 0은 중복 부재의 증거가 아니다. 2번의 확장 결과에서 중복 24개가 관찰됐지만 각 페르소나 자격·배타 배정으로 줄어든 수는 여전히 분리할 수 없다.

## 다음에 확인할 것

- 고정 시드 표본을 늘리고, 현재 나이·HARD 목표·목표 우선순위 및 선택 가능 은퇴 나이별로 기존과 확장 후보를 비교한다.
- 조기수령 자격과 페르소나별 선별·배정 이유를 조사 전용으로 관측해, 카드 수가 줄어드는 단계와 원인을 구분한다.
- 다른 생성 순서·후보 상한 및 shortlist 크기에서 결과와 실행 비용을 비교한다. 저사양 기기의 시간·메모리도 측정한다.
- 사용자 입력 → 암호화 저장·정규화 → 추천 Worker → 전략 적용 → 재분석의 도달 가능성과 동등성을 확인한다. 실제 사용자 선호와 목표를 반영하지 않은 확률 향상만으로 적용을 결정하지 않는다.

이상의 추가 검증과 별도 범위 결정 전에는 production 축 추가를 확정하지 않는다.
