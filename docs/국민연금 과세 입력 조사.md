# 국민연금 과세 입력 조사

조사일: 2026-10-29. 이 문서는 후속 작업을 위한 조사와 설계 후보이며, 구현이나 계산 계약의 변경을 확정하지 않는다.

## 결론

수급자가 공단 자료에서 확인한 **같은 과세기간의 노령연금 총수령액과 과세기준금액**을 선택적으로 입력하는 방안을 우선 검토한다. 두 금액으로 산출한 비율을 미래 연금액에 적용하는 것은 공식 확정값이 아니라 모델 가정이다. 가족수당·다른 연금·정산 등 포함 범위와 조기·연기수령 시 적용 가능성을 먼저 확인해야 한다. 이 확인과 실제 입력 가능성 검증 전에는 구현을 결정하지 않는다.

미수급자의 예상 과세기준금액을 공단 조회 화면에서 확인할 수 있는지는 공개 자료로 확인하지 못했다. 가입기간의 단순 비율로 대체하지 않는다. 입력이 없거나 사용할 수 없는 경우에는 기존 전액 과세 계산을 유지한다.

## 근거와 입력 가능성

- 국민연금공단은 과세대상 연금액을 해당 기간의 연금수령액에 2002년 이후 납입기간의 **환산소득 누계액 비율**을 곱해 산정한다고 설명한다. 가입 월수만 나눈 비율은 이 공식과 다르다. [국민연금공단 과세제도 안내](https://www.nps.or.kr/pnsinfo/ntpsklg/getOHAF0088M0.do)
- 공단의 연금소득 원천징수영수증 서비스는 수급자를 대상으로 하며, 총연금수령액·연금제외소득·과세기준금액을 설명한다. 공단은 수급자가 연말정산 모의계산 또는 원천징수영수증으로 과세기준금액을 확인할 수 있다고 안내한다. 영수증에는 여러 종류의 연금이 포함될 수 있으므로 입력에 사용할 항목과 범위의 확인이 필요하다. [영수증 서비스](https://m.nps.or.kr/elctcvlcpt/comm/getOHAC0000M5.do?menuId=MN24001061), [공단 안내](https://www.nps.or.kr/pnsinfo/ntpsklg/getOHAF0097M0.do)
- 공단은 가입자의 예상연금액 조회를 안내하지만, 확인한 공개 안내만으로는 **예상 과세기준금액도 조회 가능한지 확인할 수 없다**. 가입자가 과세 비율을 쉽게 제공할 수 있다고 가정하지 않는다. [예상연금 조회 안내](https://www.nps.or.kr/pnsinfo/ntpsklg/getOHAF0095M0.do)
- 입력 부담은 별도 인증과 자료 발급, 같은 기간·같은 종류의 세전 금액 확인, 금액 두 개의 직접 입력이다. 실제 화면과 표본 사용자를 통한 입력 가능성·오입력률은 아직 검증하지 않았다. 문서 업로드나 서버의 자료 열람은 제안하지 않는다.

## 설계 후보 — 미확정

1. 기존 국민연금 예상 월액은 그대로 유지한다. 선택 입력에서 자료의 기준 연도, 같은 기간의 해당 노령연금 세전 총수령액과 과세기준금액을 받는다. 납입 연수·세후 수령액·결정세액은 대체 입력으로 받지 않는다.
2. `0 ≤ 과세기준금액 ≤ 대응 총수령액`, 총수령액 양수, 같은 기간과 동일한 급여 범위를 검증한다. 0은 유효한 명시값이며 미입력과 구분한다. 분모에 가족수당이나 비과세 연금이 섞이지 않는 조건은 자료 양식과 제도로 확인한 후 정한다.
3. 모델에 사용한다면 확인된 비율을 고정하여 각 연도의 세전 노령연금에 적용하는 근사로 명시한다. 비율의 장래 유지, 물가·조기·연기수령 변화와 자료 기준기간의 정합성은 아직 검증되지 않았다. 확인할 수 없다면 미래 예측에 적용하지 않는다.
4. 추가 입력이 없으면 기존 전액 과세를 그대로 유지한다. 입력 오류를 0이나 100%로 조용히 보정하지 않고 사용자에게 수정 또는 미사용을 요청한다. 기존 저장 시나리오에 입력값을 만들어 넣지 않는다.
5. 결과에는 자료 기준연도, 적용된 과세 범위와 미래 비율 유지가 가정임을 밝힌다. 미입력 시 기존 전액 과세 고지는 유지한다. 대시보드 요약·전문가 상세·PDF에서 같은 조건과 의미를 사용한다.

## 구현 영향과 검증 계획

- **입력·저장:** `NationalPension`은 현재 예상 월액만 가진다. `normalizeSimulationParams`는 국민연금 객체를 새로 구성하므로 필드만 추가하면 저장 후 정규화에서 사라진다. 선택값의 검증과 보존, 0과 누락 구분, 레거시 시나리오·복사·암호화 저장·복원 및 adapter 왕복을 검증해야 한다. 평문은 기존처럼 브라우저에서만 처리한다.
- **세금:** `SimulationEngine`은 연간 세전 국민연금 전액을 `calculateNationalPensionTaxKRW`에 넘긴다. 사적연금 종합과세 비교도 같은 전액을 사용한다. 과세 부분을 도입한다면 두 경로에 같은 기준을 적용하되, 세전 총수령과 과세대상액을 별도로 유지해야 한다. 공제·세율은 기존 `taxLawProfiles.ts`를 사용한다.
- **건강보험과 현금흐름:** 현재 국민연금 세전 총액이 건강보험 계산에도 전달된다. 세금용 과세대상액으로 무조건 대체하지 않는다. 건강보험료와 피부양자 판정에 실제 적용할 소득 범위는 별도 공적 근거와 현행 모델을 확인하고, 이번 설계에서 변경을 전제하지 않는다. 소득·세금·인출·총자산 원장 보존도 검증한다.
- **추천·Worker·PDF:** UI 입력 → 암호화 저장 → 정규화·복원 → adapter → 현재 계획·자동 후보 → Worker·Monte Carlo → 대시보드·PDF의 값 보존과 동일 결과를 확인한다. 사적연금 합산 비교, 국민연금 개시 나이 변화, 명목·실질 단위도 함께 검증한다.
- **테스트:** 미입력 기존 결과 회귀, 명시적 0과 100%, 부분 과세, 잘못된 입력, 기존 데이터 복원, 사적연금 합산, 건강보험 경로 분리, 원장 보존, Worker 동등성, 화면·PDF 고지의 유무를 검증한다. 법정 예시나 공단 확인 자료를 이용한 독립적인 기대값도 필요하다.

## 구현 전 확인할 질문

- 수급 전 사용자가 예상 과세기준금액을 확인할 공식 경로가 있는가?
- 영수증의 총수령액에서 가족수당·다른 유형의 연금·정산액을 분리해 모델에 맞는 분모를 얻을 수 있는가?
- 수급 전후 납입·재평가, 조기·연기 및 분할연금 등의 변화에서 과거 비율을 미래에 고정하는 근사가 타당한가?
- 건강보험 소득 범위와 사용자 입력의 유효기간을 어떻게 다룰 것인가?
- 실제 수급자가 자료의 해당 항목을 정확히 찾고 입력할 수 있는가?

위 질문은 해결되지 않았다. 입력 계약이나 계산식을 확정하면 별도 ADR과 관련 개념 노트를 갱신한다.
